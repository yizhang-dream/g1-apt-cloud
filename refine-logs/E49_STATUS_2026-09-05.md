## 3. 诊断（四曲线对照，E45 latent 为锚）

E45 latent：rew 1.6→**2.07 上升**、kl med **64**、真走路（优化健康）。
E49-A 无界：rew 单调降、kl med 374–654（= latent 的 **4–10×**）。

**病灶**：PPO 每次更新的策略位移在裸 64d token 空间直接砸在 decoder 输入上，
过大且无缓冲——rew 下降说明它在随机游走而非优化。量级差两个来源叠加：
①KL 按维求和，64d vs 16d 天然 ~4×；②**冻结 VAE 原来起 KL 冲击缓冲器作用**
（z 大位移经 VAE 映射后仍是流形近邻 token，decoder 吃得下）——这是 VAE 的
隐藏第四角色（前三：流形约束/低维输出/相位钟），把 VAE vs 直出的归因又推进一层。
配置侧：每 iter ~30 次梯度步（5 epochs × minibatch 512 @ lr 3e-4）对裸 token 过热。

## 3b. 诊断修正（2026-09-05 晚，owner 评审采纳；本地五处代码核验属实）

核验基线：本地 `apt_g1/isaac/` 自 561ae6c 零改动；服务器执行根
ppo_core/train/env 三文件 blob 哈希与 561ae6c 逐位一致（ea46ea14/149faed3/
c3916039）→ 以下结论适用于 E49 历史 run。

1. **指标身份错误（最关键）**：日志 `kl` =
   KL(π_θ(phase/token 头) ‖ N(prior, I))（ppo_core.py `kl_normal_std_normal`/
   `kl_normal`），是**对固定先验的偏离度，不是 PPO 新旧策略 KL**。初始
   log_std=-4 时每维 ≈3.5 → 16d 初始 ≈**56**、64d ≈**224**（策略零更新即有，
   量级差大半来自维度×初始方差）。且该指标混杂数值方差收缩（log_std 每降 1
   ≈ +1/维）——增大探索方差也能降它，读不出"每次更新幅度"。
   → **撤回预注册判据"修复 run kl med ≤~150"**（tracker E49 结论 3 同步修订）。
   增量口径（各自减初始底噪）下 token 臂漂移确实更多——"离先验更远"成立，
   但"更新过猛/随机游走"推断不成立。
2. **"每 iter ~30 次梯度步"错误**：`num_epochs=5` 存了但 update() 无 epoch
   循环，单遍 minibatch = 128×24/512 = **6 次/iter**；"epochs 5→2"原为空操作。
   "64d 过热"论断删除。
3. **GAE 边界缺陷（实锤，修复优先级最高）**：compute_gae 收了 dones 未用，
   `cont=~truncated` 同时控自举与递推 → **摔倒步不切断**（Isaac DirectRLEnv
   边界返回复位后 obs，下一局价值/回报被接到上一局）；**超时步自举被错误
   清零**（应切断递推但保留终末自举）。足以污染训练方向；是否 E49 崩坏唯一
   原因未定——latent 臂同缺陷但摔倒频率不同，"E45–E47 表现好"不能反推训练
   器正确。
4. **aux 12d 未执行却进 PPO ratio/熵**（token/latent 模式丢弃 aux 输出但联合
   logp 参与裁剪与熵奖励；E45–E47 同样带病——修正后新旧 run 不再严格可比，
   以修正训练器为新参照系）。
5. **日志 vx = 水平速度模长 × rollout 末时刻均值**（非前后向速度）；
   "vx=1.67 前进超速"表述作废。
6. **E46 勘误**：§3 的"E45 latent 锚"曲线实取自 `isaac_e45_e39_from0.log`
   = **E46**（从零+E39 VAE，03_OUTPUTS_INDEX §3 口径）。§3 挂账"不影响本
   诊断"撤回——锚曲线身份影响机制归因，kl med 64 属于 E46。

**随之降级**："PPO 在随机游走"→"观察到训练退化，机制未定"；"VAE=KL 冲击
缓冲器（隐藏第四角色）"→**未证实假设**（需实测 token/关节目标对策略位移的
敏感度）；KL-to-init 正则降级不优先（锚的是初始策略非每次更新，初始方差
极小时会锁死学习）。

**修正后的顺序（owner 决策）**：修训练器（GAE/aux/真指标 approx_kl·clip_frac·
act_std/vx_fwd）+ 确定性测试 + it_0 快照与未训练对照（确定性初始策略 ≈ 固定
官方均值 token 回放，量化 it_50 真实学习量）→ 原 LR 基线 → 再谈降温。已知
残留：truncation 自举仍为 0（复位后 obs 无终末价值可用，rsl_rl 生态同病；
稳态下 trunc 步占比 ~2.4%），若修正基线后期仍劣化再按 rsl_rl 式 reward-
bootstrap 处理；clip 不保证更新受控，必要时 KL 早停（后置）。
