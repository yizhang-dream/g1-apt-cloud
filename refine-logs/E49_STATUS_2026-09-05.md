## 3. 诊断（四曲线对照，E45 latent 为锚）

E45 latent：rew 1.6→**2.07 上升**、kl med **64**、真走路（优化健康）。
E49-A 无界：rew 单调降、kl med 374–654（= latent 的 **4–10×**）。

**病灶**：PPO 每次更新的策略位移在裸 64d token 空间直接砸在 decoder 输入上，
过大且无缓冲——rew 下降说明它在随机游走而非优化。量级差两个来源叠加：
①KL 按维求和，64d vs 16d 天然 ~4×；②**冻结 VAE 原来起 KL 冲击缓冲器作用**
（z 大位移经 VAE 映射后仍是流形近邻 token，decoder 吃得下）——这是 VAE 的
隐藏第四角色（前三：流形约束/低维输出/相位钟），把 VAE vs 直出的归因又推进一层。
配置侧：每 iter ~30 次梯度步（5 epochs × minibatch 512 @ lr 3e-4）对裸 token 过热。
【挂账待核：E45 对照曲线取自 `isaac_e45_e39_from0.log`，与 tracker E45 行
e27/vae.pt 记载有 VAE 版本出入，不影响本诊断（latent 模式稳定性对照成立）】

## 4. 修复菜单（按性价比排序；①为已定首选）

1. **PPO 降温（首选最小实验）**：lr 3e-4→1e-4、epochs 5→2。**发射前一步**：
   `train_apt_isaac.py` 需补 `--ppo-epochs` 旗标（PPOTrainer 默认 num_epochs=5
   未暴露 CLI；`--lr` 已有）+ eval/部署照常（sync pull → cp 三件）。
   发射命令（补旗标后）：
   ```bash
   bash /tmp/run_apt_isaac.sh .../train_apt_isaac.py --num-envs 128 --iters 1000 \
     --env apt --token-mode --token-stats .../e49/token_stats_e49.npz \
     --lr 1e-4 --ppo-epochs 2 --seed 0 --out .../isaac_e49a_cool_s0
   ```
   先 1 seed × 500–1000 it 看曲线形态（rew 上升/kl 回落即续跑，否则停）。
2. **KL-to-init 正则**：token 空间锚定初值（软 tanh），机制 = 手工重建 VAE
   缓冲作用；若①失败再上（需新写损失项）。
3. **best-snapshot 规程**：峰值总在 it_50–100，把「短训练+快照选优+early-stop」
   定为规程（零科学改动，纯省算力；无论①结果如何都可采纳）。
4. **长 episode 20s→60s**：治评测暴露面不治 kl 病灶，靠后。
