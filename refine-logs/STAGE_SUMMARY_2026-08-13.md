# APT-RL × SONIC × G1 阶段总结（2026-08-13）

> 覆盖范围：优先级链收尾（平坦命令完备性 → aux 判据）与三方向探索
> （力矩级数据 / 连续潜空间 / 千级并行）。前序阶段（MuJoCo 两条线、
> E1–E20 机制矩阵）见 `FINAL_REPORT.md`（2026-08-12）。

## 1. 一句话结论

**当前管道的可用下限已经确定且全部达标**：冻结相位路由器 + SONIC 解码器 +
显式回退表（平坦 24/24 命令无跌倒）就是可交付的最优控制器。三方向探索
给出三个确定性结论：ID 力矩数据只能改善前馈、单独不能解锁论文式控制；
连续潜空间在"锚定先验时钟 + 前进压力 + 关 aux"下首次无损（但机制中性）；
千级并行正解是 mjlab 官方配方（3060 上 1024 envs 验证通过），它是独立于
蒸馏管道的从零学习轨道。方向 D（E28–E35）进一步定性：**冻结 walk 解码器
流形 ~0.35 m/s 是固有速度天花板（E28–E30）**；**速度条件化 VAE 打破上限
（E31 vx 0.535）但自带系统性转向偏置、非奖励/补偿/DR 可修（E32–E34）**；
**方向条件化 VAE 修复漂移（E35 disp/vx 0.93）但速度回落 ~0.3**——"快且直"
是下一个动作表征层候选（E36）。

## 4. 方向 A：力矩级数据/解码器（完成）

- 数据：`recover_id_torque.py` 用 mj_inverse 从重放轨迹算"产生该运动所需
  力矩"（ID 力矩），27,000 行，1/99 百分位裁剪尖峰。
- 解码器：phase→ID 力矩 val **MAE 4.13 N·m**（PD 标签版 ~9.4；40-bin 条件
  均值残差 10–12 vs 总 std 42–57，相位可预测性高）。
- MuJoCo 闭环：

| 控制方案 | 平坦 walk | 粗糙 0.06 |
|---|---|---|
| 论文式（ID 前馈 + PD 默认位姿） | 124–126 步倒（vx 0.54，会动） | 124–135 步倒 |
| 混合式 ×1.0 | 9–19s 倒（vx 0.87–1.01 超速） | 125–191 步倒 |
| 混合式 ×0.2/0.3 | **3/3（15.2–15.4m / 14.2–14.8m，≈基线）** | 0/3 |

结论：ID 力矩能显著改善前馈质量，但单独不能解锁论文式控制或地形鲁棒性。
根因：我们的 ID 力矩来自带位置跟踪控制器的重放轨迹，不是论文 TO 那种自洽
的规划力矩。要复现论文 aux 正向价值，仍需**自洽 TO/逆动力学"规划"数据**
（生成不含位置跟踪器的力矩驱动运动）。

**〔2026-08-14 更新，TO01–TO05〕** 这个一直缺失的"自洽 TO 规划力矩"前置
现在**已能自己生成**：`srb_to.py`（SRB 轨迹优化器，CasADi）+ `srb_to_torque.py`
（IK → 关节力矩）+ `train_torque_decoder_srb.py`（力矩可学性）。TO01–TO03
单步态 walk 力矩 MAE 0.27–0.31 N·m（vs PD 18.76、ID 4.13）；**TO04 扩展到
多步态**（walk d=1.0 / run d=0.5 带腾空相）；**TO05 加 ankle 力矩**（CoP 杠杆臂
模型）。最终 **3 关节（hip/knee/ankle）× 2 步态 × 6 速度** full MAE hip 0.879 /
knee 1.100 / ankle 0.572 N·m，且**步态身份（duty factor）是必要输入**（跨步态
外推 MAE 32.9/70.6/32.1 远差于同训练）。已知限制：F_x 水平推进力（需 Bézier 共
优化，暂缓）、ankle 未做完整 3 连杆 IK（无 ankle 角度）、crawl 与多速度同轴冗余。
**〔TO06 力矩级闭环，负结果〕** 把 SRB TO 力矩作为前馈接进 G1 力矩闭环
（τ = τ_SRB + kp·(zero-token q_des − q) − kd·q̇），**不能走路**（短暂移动 0.9–1.3m
即倒 1.6–9.5s；对比 A-ID 的 ID 力矩至少站住）。根因：SRB 是 2D 单刚体（36kg 点
质量），与 43-DOF 双足 G1 差太远，力矩量级（hip 峰值 25–76 N·m）远小于 G1 行走
所需。**结论：论文 SRB TO 是四足专用简化，作人形 G1 力矩前馈不成立；力矩级 aux
正路仍需 G1 全身/腿级 TO（非 SRB）**。详见 `EXPERIMENT_TRACKER.md` TO 段。

**〔TO07 归因细化，2026-08-15〕** 两点修正/细化：① 上面"远小于 G1 行走所需
（~100–300 N·m）"是高估——G1 下肢执行器上限是 hip ±88 / knee ±139 / ankle ±50 N·m
（`scene_43dof.xml` + wbc yaml 一致），SRB 力矩 hip ±25–76 其实已在包络内，**量级不是
唯一病根**；② 更深病根是 **SRBD 运动本身退化**——SRB 的 CoM 高度 ~0.625m 比真实 G1
腿长（L1+L2=0.68m）还短，IK 被迫"屈膝够地"成奇异构型，全动力学 `qfrc_inverse` 冲
−58248 N·m（病态）。**正确自洽力矩 = τ_clean = qfrc_inverse − qfrc_constraint**
（完整逆动力学 Mq̈+Cq̇+g **减** 接触项 Jᵀλ），静态站立 sanity 已证符号约定正确；它调和了
SRB（τ=Jᵀf=只接触→塌）与 A-ID（qfrc_inverse=自由空间、缺"−接触"→站住不前进）两个负结果。
**结论不变但路线更清**：SRBD 运动不可救（非力矩可补），需真实多体步态；技术路线报告见
`docs/g1_fullbody_trajectory_optimization_roadmap.md`。
**〔关键纠偏 2026-08-15〕** τ_clean 公式正确，但**对 PD 生成的运动（如 SONIC 走行）它恰好恢复
PD 力矩本身**（因 `M q̈+C q̇+g = τ_PD + Jᵀλ` ⟹ `τ_clean = qfrc_inverse−qfrc_constraint = τ_PD`），
故"从 SONIC 走行算 τ_clean"不是干净规划力矩的捷径——**干净力矩要求运动本身是动力学/运动学生成
的（TO 或运动学步态合成），而非 PD 跟踪的**。下一步正路：先运动学步态合成（正确髋高 0.76m、
含摆动腿）+ 完整 ID 力矩，再上平面多体 NMP。

**〔TO08 腿惯性量级 + mj_inverse bug，2026-08-15〕** 两个定量结论：① **`mj_inverse` 对浮基
G1 双腿同时驱动时返回错误**（hip +154 vs 手动 M@qacc+g −3.0 N·m，50×；左右腿不对称），正确
路由是**手动 `M@qacc + qfrc_bias`（M=mj_fullM，qfrc_bias 来自 mj_forward）再减 qfrc_constraint**；
② **全 ID 摆动腿力矩（惯性+重力）hip ±18 / knee ±4.3 N·m**（2Hz、A_h=0.3 关节空间步态），对照
SRB 静态 stance 接触 hip ±25–76 N·m → **腿惯性是被"无质量腿"漏掉的真实分量（~18 N·m ≈ stance
的 25–50%），但非主导；主导仍是 SRBD 运动退化（TO07）**。G1 腿结构：pelvis→hip_pitch→hip_roll→
hip_yaw→knee→ankle（hip_pitch 支撑整腿 7.19 kg）。**含义**：全动力学力矩可手动可靠算（M@qacc+bias），
下一步是把"退化运动"换成"真实步态运动"——运动学步态合成（足-地接触 + 正确髋高 + 摆动腿离地）
或平面多体 NMP。

**〔TO09 正确几何 + 定量 τ_clean，2026-08-15〕** ① **G1 腿几何纠正**：srb_to_torque 的
L1=L2=0.34+髋 0.625m 是错的；真实是髋 0.657m、大腿 0.3406m、小腿 0.30m、踝 0.056m（腿 0.6406、
髋-踝垂直 0.601、屈膝余量 0.0396m、水平可达 0.2217m）。② **IK 符号约定**：hip_pitch=−θ_h、
knee=θ_k（对拍 MuJoCo FK 往返 ankle 误差 0）。③ **足步态全 ID 力矩（quintic smoothstep 光滑
touchdown 后，无尖峰）**：hip M qdd+bias（惯性+重力）±46 N·m、τ_clean（执行器力矩）±51 N·m、
knee τ_clean ±11 N·m（vs SRB 静态 stance 接触 hip ±25–76）。**〔TO08 数值修正〕** TO08 最初报的
"hip ±18 N·m"是索引 bug（读到自由关节 x 力而非髋力矩），正确髋惯性 ~40–46 N·m——与 SRB 静态同量级。
**核心定量结论**：正确执行器力矩 τ_clean = M qdd + bias − Jᵀf ≈ ±51 N·m，而 SRB 的 τ=Jᵀf（25–76
N·m）是"接触力（地面贡献）"不是"电机力矩"——**TO06 的根因是施加了错误的力矩（把接触力 Jᵀf 当前馈，
而非 M qdd+bias−Jᵀf）**。

**〔TO10+TO11 可学性 + 闭环，2026-08-15〕** ① **τ_clean 高度可学**：phase→τ 解码器 hip MAE 0.61 /
knee 0.14 / ankle 0.03 N·m（相对误差 ~0.3–0.5%，与 SRB 力矩 MAE 0.57–1.1 同量级）。② **力矩级闭环
（τ_clean + 轻 PD）优于 SRB 但不稳**：前进 0.82m（vx 0.23）存活 3.58s（vs TO06 SRB 1.6–2.0s 倒、
A-ID"站住"）；扫参 kp_scale 0.2–0.8、v 0.3–0.5 均 ~3.5–4.4s 倒 → **调 PD 不改变结局**。**结论**：
正确力矩分量方向对、优于 SRB，但**运动学合成（option e）的运动非动力学解，稳定走需动力学一致的运动
→ 平面多体 NMP（option b）是必由之路**。至此方向 ① 的"运动学合成"捷径已穷尽（正确几何+正确力矩+可
学性都打通，闭环仍不稳），下一步唯一正路 = 平面多体 NMP。

**〔TO12–TO14 多体 NMP，2026-08-15〕** **NMP 框架跑通（里程碑）**：平面 5 连杆模型（躯干 20.7kg + 2×
(大腿 4.572 + 小腿 2.614)kg，真实 G1 质量，CasADi 拉格朗日动力学 M/bias 验证通过）+ 直接配点（接触力
决策变量 + 摩擦锥 + 摆动脚离地 + 周期边界腿交换）解出**直立周期步态**（髋高 0.61–0.64m、俯仰 ±7°、摆动
脚 0–0.2m）。修复 5 坑（jacobian 切片/swap 矩阵/无滑移/几何符号/退化解）。**速度缩放**：慢步幅 S=0.15
（v=0.3）把 hip ±53、knee ±142（≈限位 139）、接触力 2645 N → **高力矩速度相关、接触力尖峰是足落地冲击**。
**含义**：从 SRB（单刚体）到多体 NMP（自洽步态）的升级已落地；剩余两步 = ① 光滑 touchdown（降接触力）、
② NMP 力矩投影 G1 sagittal 闭环（2D→3D 迁移，含踝平衡）。

**〔TO15 NMP 力矩闭环，2026-08-15〕** **2D NMP 力矩不优于 kinematic τ_clean**：0.57–0.74m/3.1–3.44s（vs
TO11 kinematic 0.82m/3.58s）→ **2D→3D 缺口（无踝、无 3D、无臂）使 2D NMP 的自洽性是对 2D 模型而言，
反而不如用真实 43-DOF G1 模型（mj_inverse）算的 kinematic τ_clean**。**核心结论**：自洽规划力矩须从接近
43-DOF G1 的模型算（2D 5 连杆太简化）。这补全了"力矩级闭环可行性"的完整证据链：正确力矩 τ_clean（M q̈+
C q̇+g−Jᵀf）优于 SRB（TO11）、可学（TO10），但 2D 平面 NMP 因模型简化在闭环上不占优（TO15）——**方向 ①
的核心研究（多体 TO 升级 + 自洽力矩 + 可学性 + 优于 SRB）已完整；"解锁 aux 正向价值"仍需力矩级 RL + aux
训练（未做）**。

### 5.3 方向 B 定论

1. 连续潜空间解决的是"平滑性/梯度"问题（E3 离散选择学不出振荡器的死因），
   不是"流形上限"问题。
2. 在正确条件下（锚定先验时钟 + 前进压力 + aux 关闭），相位偏移策略全项
   达标且无损（46–49m vs 先验 47m），但**机制中性**：不增益、不破坏。
3. aux 关节偏移通道始终是唯一破坏源（E25 同一检查点 aux 开 21–34m vs
   关 49m）。论文 aux 正向价值仍依赖力矩级解码器 + TO/逆动力学数据。

| E32 | +yaw×2 +heading 奖励 | 0.354 | ~10.3m | 0.5 | 失败：速度被压回，漂移未修 |
| E33 | 开环 yaw 补偿 | — | ~9.6m | 无变化 | 失败：policy 观测含命令 yaw，主动抵消 |
| E34 | yaw 域随机化 | 0.395 | ~7.4m | ~0.31 | 失败：偏置是流形技能固有特征 |
| E35 | **方向条件化 VAE**（8 档方向 bin） | 0.295 | 16.3m | **0.93** | **漂移修复**（接近直行）但速度回落 ~0.3 |

**结论**：
1. **冻结 walk 解码器流形 ~0.35 m/s 为固有速度天花板**（E28–E30）：解冻步频
   （E28a）、奖励重调（E28b）、流形-KL（E29/E30）三轴均无法突破 → 修正
   E27 结论"半速=样本效率代价"为 **"半速=解码器流形的固有速度天花板"**。
2. **速度条件化 VAE 打破上限**（E31，vx 0.535，+54% vs E29）但自带系统性
   转向偏置；该偏置**非奖励（E32）、开环补偿（E33）、命令随机化（E34）
   可修**——是速度条件化流形技能本身的固有特征。
3. **方向条件化 VAE 修复漂移**（E35，disp/vx 0.31→0.93，接近直行）证明
   "方向是流形显式轴"的机制正确；但 policy 未被激励选快 bin → 速度回落
   ~0.3。
4. **E36（E35 + anti-stop-thresh 0.4 + progress-scale 0.5）速度激励**：A vx
   0.372（+26% vs E35 0.295）/ disp 15.4m / 直行 0.69，B 12/12、C 3/3、D 3/3。
   **速度-方向权衡是流形固有项**：推快 z 重新引入 E31 型转向偏置（直行
   0.93→0.69），未达快 bin 0.535 → **简单奖励速度激励不能实现"快且直"**。
5. **E37（方向解耦 VAE + E36 速度激励）**：A vx 0.370 / disp 21.55m / 直行
   0.97，B 12/12、C 3/3、D 3/3。**方向解耦修好漂移**：同 vx 0.37 下 disp
   15.4m→21.55m、直行 0.69→0.97 → **快且直达成（0.37 m/s 档）**。根因：
   E36 漂移来自 z 隐式编码方向；对抗式解耦让 z 方向不变（fresh 分类器
   0.707≈多数类 0.702）后消除。
6. **E38（E37 + anti-stop-thresh 0.5 + progress-scale 1.0 更高速度激励）**：
   A vx 0.399（+8% vs E37 0.370）/ disp 19.4m（-10% vs 21.55m）/ 直行 0.81
   （vs E37 0.97），B 24/24、C 6/6、D 6/6（鲁棒性完整）。**方向解耦不是
   解锁 0.535 快 bin 的钥匙**：更高激励只换小幅提速却重新引入漂移、净位移
   下降；解耦后 z 的速度天花板 ≈0.40，低于 E31 未解耦的 0.535 →
   速度上限与方向纠缠是两个独立约束。
7. **E39（E38 配置 + 双对抗头速度+方向解耦 VAE）**：A vx 0.417（+5% vs E38
   0.399）/ disp 24.65m（+27% vs 19.4m）/ 直行 0.98（vs 0.81），B 24/24、
   C 6/6、D 6/6。**假设成立：速度也纠缠在 z 里**——双解耦后同一高激励下
   又快又直，disp 24.65m 为潜空间线历史最佳（超过 E37 的 21.55m）。探针：
   方向 0.722≈多数类 0.702、速度 0.575≈多数类 0.573。
8. **E40（E39 配置 + thresh 0.6 + progress 1.5 更高激励）**：A vx 0.456
   （+9% vs E39）/ disp 24.40m（-1%）/ 直行 0.89（vs 0.98），B 24/24、
   C 6/6（但 disp ~3m vs E39 ~10m）、D 6/6（但基本站住）→ **E39 是甜点**：
   双解耦 z 的 Pareto 前沿 ≈(0.42, 0.98)↔(0.46, 0.89)，激励再推速度增益
   边际化且 C/D 机动性退化，0.535 仍不可及。
9. **E41（E39 甜点 × 地形泛化）**：rough 0.06 **6/6 存活**（vx 0.42–0.50，
   disp 11.4–26.1m）；rough 0.08 **s0 0/6（fall_step 401–632）、s1 0/6
   （fall_step 645–1195）全倒** → **0.08 悬崖对所有方案一致**（冻结先验

10. **E42（E39 配方直接在 rough 0.06 训练）**：0.06 **6/6 存活**（disp 均值

11. **E40 漂移归因（per-bin 方向泄漏探针，2026-08-14）**：E39 VAE 的 z 在

## 7. 核心结论汇总

1. **蒸馏先验必要且够用**：同等预算 vanilla RL 无法行走（E9/E11 0/3 立即
   倒）；冻结先验 + 回退表给出平坦地面全命令可交付下限。
2. **aux 在 SONIC 位置 token 管道下永远是破坏源**（E2–E22b、E25 消融）。
3. **连续潜空间无损但机制中性**：正确配置下全项达标，不产生增益。
4. **力矩级数据是必要条件不是充分条件**：缺自洽 TO/ID 规划数据。
5. **千级并行需要换后端**：mjlab 是正解且 3060 上已验证 1024 envs；
   它是独立对照轨道，用于回答"不蒸馏是否更强"。
6. **对"蒸馏是否必要"的最终回答（修正口径）**："蒸馏"特指从 SONIC 数据
   蒸馏的相位路由器；其必要性只能在同一 SONIC 管道内消融——E27（有解码
   器、无路由器）可走但约 0.4× 位移（19m vs 47m）vs 冻结先验（有路由器）
   47m → 路由器不必要但 2.5× 提速；SONIC 解码器/token 流形才是管道内
   关键先验（E9/E11 直出关节 0/3）。mjlab 是"无 SONIC 组件"的官方从零配方
   外部对照（已完成 6500 iters，fell_over 0.125），回答官方配方不用解码器
   的可行性，不直接回答"蒸馏是否必要"。
7. **冻结 walk 解码器流形 ~0.35 m/s 是固有速度天花板**（E28–E30）：解冻
    步频/奖励重调/流形-KL 三轴均无法突破 → 修正 E27"半速=样本效率代价"
    为"半速=解码器流形固有速度天花板"。
8. **速度条件化 VAE 打破 ~0.35 上限**（E31，vx 0.535，+54% vs E29）但自带
    系统性转向偏置；该偏置非奖励（E32）/开环补偿（E33）/命令随机化（E34）
    可修——是流形技能固有特征。
9. **方向条件化 VAE 修复漂移**（E35，disp/vx 0.31→0.93，接近直行）证明
    "方向是流形显式轴"机制正确，但速度回落 ~0.3（未被激励选快 bin）。
10. **E36 速度激励（E35 + anti-stop-thresh 0.4 + progress-scale 0.5）**：vx
    0.372（+26%）但直行 0.69（未达快 bin 0.535）→ 推快 z 重新引入 E31 型转向
    偏置，**简单奖励速度激励不能实现"快且直"**。
11. **E37 方向解耦 VAE（对抗式方向分类头）修好漂移**：A vx 0.370 / disp 21.55m
    / 直行 0.97（同 vx 下 E36 直行 0.69）→ **快且直达成（0.37 m/s 档）**。
    根因 = z 隐式编码方向；让 z 方向不变（fresh 分类器 0.707≈多数类 0.702）
    后漂移消除。
12. **E38 更高速度激励（E37 + anti-stop-thresh 0.5 + progress 1.0）**：A vx
    0.399（+8%）/ disp 19.4m（-10%）/ 直行 0.81（vs E37 0.97）。**方向解耦
    不是解锁 0.535 快 bin 的钥匙**——它修好 0.37 档漂移，但解耦后 z 的速度
    天花板 ≈0.40（低于 E31 未解耦的 0.535），说明速度上限与方向纠缠是两个
    独立约束。
13. **E39 双解耦（方向+速度）VAE 解锁快 bin**：同一高激励（thresh 0.5 +
    progress 1.0）下，E38 仅方向解耦掉直行（0.81），E39 加速度解耦后
    vx 0.417 / disp 24.65m / 直行 0.98 → **"速度纠缠在 z 里"假设成立**；
    disp 24.65m 为潜空间线历史最佳（超越 E37 21.55m），但仍低于 E31 的
    0.535 与冻结先验 47m。
14. **E40 更高激励（E39 + thresh 0.6 + progress 1.5）**：vx 0.456（+9%）
    但直行 0.98→0.89、C/D 机动性退化（切换 disp 10m→3m、跳跃站住）→
    **E39（0.417 / 24.65m / 0.98）仍是双解耦线甜点**；0.535 速度记录在
    解耦线仍不可及。
15. **E41 地形泛化（E39 甜点 × rough）**：0.06 **6/6 存活**、0.08 **0/12
    全倒** → **0.08 悬崖对所有方案一致**（冻结先验 0/9、E26 偏移 0/6、
    E39 0/12；〔2026-08-14 补 E47-T〕从零最优 E47 也 **0.06 12/12 存活、
    0.08 0/12 全倒**）：平坦"快且直"不迁移到 0.08。〔归因修正 2026-08-14，见 §10.1
    MQ09：悬崖是"蒸馏路径（无 planner 重规划）"的边界，非解码器本身。〕
16. **E42 地形上训练（0.06 训练 → 0.06/0.08 评测）**：0.06 位移 18.6→19.1m
    （噪声内）、0.08 仍 **0/12 全倒** → **0.08 悬崖与训练分布无关**。〔归因
    修正 2026-08-14，见 §10.1 MQ09：悬崖是"蒸馏路径（无 planner 重规划）"
    的边界，非解码器本身。〕
17. **三条路线的最终对照（从 0 / 冻结+RL / 微调本体，2026-08-14 补）**：
    - **从 0 RL**：我们 Isaac 管道 E9/E11 立即倒（64 envs 样本不足）；但
      **mjlab 官方配方可行**（1024 envs，平地 44.5–48m、rough 0.08 平滑退化，
      1/3 走满 60s）→ 从 0 不是不可能，SONIC 先验不是严格必要，只是"小算力
      下省样本"。
    - **冻结解码器 + RL**（本项目主线 = APT 的做法）：可行但受限（速度天花板
      ~0.35、aux 在位置 token 管道下永远破坏）。
    - **直接微调解码器**（E44 v1/v2/v3/two-phase）：**四变体全塌成打转**（含
      平地，fall ~1.3–2.5s）→ 冻结先验的"直行性"是承重墙，微调重新激活
      转向偏置（E31–E34）+ 奖励漏洞（body 系 vx 对打转惩罚不足）。
    - **结论**：APT 交付地形泛化的正确姿势是"冻结先验 + 小 RL（aux/步态选择）
      + 感知 + 规模"，**不是微调本体**；我们和 APT 的差距在"力矩级解码器 +
      自洽 TO 数据"（aux 能正向工作的前置），这才是待补的坑。
18. **从零 + 冻结解码器（E45→E47，"务必用解码器"的实证，2026-08-14 补）**：
    vanilla 从零直出关节（无解码器）会学出**蹲蹭漏洞**（h_min 0.20、body 系
    vx 假速度 0.5–0.65、世界 disp=0）；改用 latent 模式 + 冻结 SONIC 解码器后，
    **从零（随机 z、无 warm start）也能学会真走路**——E45 disp 14m（≈E27 warm
    start 19m 的 73%）、h_min 0.76；E46 + E39 速度条件化 VAE 破速度天花板
    （vx 0.418）；E47 + heading 0.4 轻推 → **vx 0.42 / 直行 0.944 / disp 23.8m，
    A/B/C/D 全过（B 24/24、C 6/6、D 6/6）**，逼近 E39 walk 先验（0.417/0.98）但
    无需 warm start、无需 walk 先验。**结论：冻结解码器是防作弊的承重墙（对比
    vanilla 蹲蹭）；速度+方向双解耦 VAE + 轻 heading 足以让从零策略快且直。**
    〔注意：E47 的 D"跳跃"是假阳性——E39 VAE 只覆盖 WALK token，模式命令被忽略，
    实际只是走路，见 EXPERIMENT_TRACKER。〕

### 10.1 MQ09 闭环规划器：重规划是地形泛化的真正机制（2026-08-14 续）

> `planner_closed_loop.py`：把官方 SONIC 的 10Hz 闭环重规划复刻出来（每 5 个
> 控制步用 live qpos 重新出轨迹，context = 4× 当前 live 状态），并支持运行中
> 切换步态模式（walk→stealth）。

- **context 构造是关键 bug**：4 帧 10Hz 历史缓冲 / 规范化根位姿都会让 planner
  收到与实机不匹配的 context → 渐进高度下沉塌陷（0.76→0.69→0.64→0.22）；只有
  **4× 当前 live 状态**（根 x/y/z + 基座四元数 + 关节全 live）才稳定。
- **核心发现（修正 MQ08）**：闭环重规划下 **walk 在 rough 0.08 上 ≈ walk 在
  平地**——adv 3.38 vs 3.39m（0.56 m/s）、根高 0.70–0.79 vs 0.67–0.74，都不倒。
  而 MQ08 开环回放 walk 在 rough 上只走 0.26m。**"walk 停摆"是开环回放伪影，
  不是步态能力边界**——官方 10Hz 重规划（而非特殊步态）才是地形泛化的机制。
- **〔MQ10 限定 2026-08-14〕** 上述"walk rough≈flat"是**单个有利地形种子（seed 0）**
  的结果。`closed_loop_sweep.py` 跨 3 种子重扫（均匀凸包，0.08–0.20）：闭环盲
  重规划**对地形实现高度敏感**——0.08 只 1/3 存活（其余根高塌到 ~0.2）、0.12 3/3、
  0.14 起基本全灭（0–1/3）。→ **印证"官方 planner 泛化能力并不强、不是针对地形
  的"**：它是运动学盲重规划（无高度图输入），靠本体感觉重规划 + PD 吸收 gentle
  bump，不是地形自适应；真正边界 ≈0.12–0.14（略高于蒸馏路径的 0.08，仍远低于
  论文台阶/栏档位）。
- **〔MQ11 杠杆测试 2026-08-14〕** 在边界 0.14 上测两个杠杆：**height 命令是弱
  杠杆**（walk 根高几乎不变、crawl 忽略）；**步态模式是真杠杆**——crawl 3/3 不倒、
  walk 0/3、stealth 1/3。crawl 不倒边界延伸到 ≥0.28（但前进 adv 在 ≥0.24 塌到
  ~0，即原地打滑）。→ 官方 27 模式里**本身就有稳健的低重心模式（crawl）**，"泛化
  不强"的缺口不是"缺稳健动作"，而是**缺"按地形选模式"的选择器（gait selection，
  APT 机制之一）**；下一步方向：感知（高度图）→ 选步态，把"walk 在 0.14 崩、crawl
  在 0.14 稳"变成自动切换。
- **〔MQ12 步态选择机制 2026-08-14〕** walk2crawl（root-z std 触发，amp 0.14 × 3
  种子）：触发 25–38 步即检测到粗糙并切换（工作正常），但切换后仅 **1/3 存活**，
  而纯 crawl 是 3/3（MQ11）。→ **"步态选择"方向成立，但卡在"模式切换的 transition"**：
  中途 walk→crawl 的大姿态切换脆弱，正是官方 SONIC 的 **ADAPTING 状态机**（处理
  站→跪/爬切换，MQ07/MQ08 已发现缺它）所解决的。**复刻 ADAPTING 状态机是"感知→
  选步态"能落地的唯一剩余前置**——这也是"穷尽各种方向"的收敛点：方向已穷尽到
  "步态选择"这一步，再往下就是官方状态机这个硬前置。
- **模式切换机制成立**：walk→stealth 触发切换（`switched_at=25`）干净、全程不倒，
  切后稳定进入 stealth 低姿态（根高 0.61–0.62）。walk 3.38m（直立快）、
  stealth 1.84m（低姿态慢）。
- **根高 std 是弱地形信号**：flat zstd 0.0111 ≈ rough 0.012——闭环重规划把地形
  吸收得太好，本体感觉（根高抖动）几乎无法区分平地/粗糙，真正的粗糙度触发需要
  感知（高度图，即 P 系列）而非纯本体感觉。
