## 0. 这文档是干什么的

我们用 NVIDIA 官方的 SONIC 人体动作跟踪模型 + 宇树 G1 人形机器人，试图复现一篇论文（APT-RL）的
"先学走路先验、再用强化学习微调"的路线，最终目标是：**让 G1 在没有任何外部辅助（不挂橡皮筋）的
情况下，在平地和粗糙地形上长时间稳定行走，并且能听命令转向、横移、倒走、跳跃。**

实验从 2026-08-11 开始，到 2026-08-12 夜里经历了两个平台（MuJoCo → Isaac Lab）、十几个实验系列、
几十次训练、无数次"此路不通"。这份文档就是把整个过程按"人话"重写一遍，确保：

1. 中途发现的小结论一条不丢；
2. 中途探索过但放弃的方向都写清楚"为什么放弃"；
3. 别人看完能直接接上，不需要重新爬一遍日志。

## 1. 一句话总结

**在平坦地面上，用官方 SONIC 数据蒸馏出来的"相位路由器 + 官方解码器"（不挂橡皮筋）就是我们目前
能做出来的最强控制器：前进、倒走、慢走、跳跃、转向、横移都能做，60 秒连续行走 3/3 种子通过。
所有想在这之上"锦上添花"的强化学习组件（辅助动作、地形地图、步态选择）不但没有加分，反而把先验
搞坏。根本原因是：我们用的数据（SONIC 位置 token）和论文用的数据（轨迹优化产生的力矩）不是一类
东西——论文能成立的机制，在我们的替代管线上没有生效条件。**

更直白地说：

- 蒸馏这条路**是可行的**，而且是最便宜、最稳的；
- 但它的上限就是"官方 SONIC 在无辅助环境里本身能走多久"；
- 官方 SONIC 对转向、横移这类动作的长效数据本身就生成不好（95–270 步内倒），这不是我们做错了，
  而是 SONIC 的架构特性（短时程跟踪 + 有损 token 压缩 + 数据方向覆盖不均）决定的；
- 想突破上限，缺的不是更多数据或更好的网络，而是**带力矩标注的数据（轨迹优化/逆动力学）+ 力矩级
  解码器 + 大规模并行强化学习**，这些要么换硬件，要么换数据来源。

## 2. 背景：我们本来想干什么

### 2.1 论文（APT-RL）是怎么做的

APT-RL 论文的路线可以拆成四层：

| 层 | 论文做法 | 一句话解释 |
|---|---|---|
| 数据 | 轨迹优化（TO）生成大量"2D 周期轨道 + 力矩标签"，速度覆盖 −2~7 m/s | 数据是"凭空生成"的，命令空间全覆盖，物理上干净 |
| 先验 | 用 TVAE（时序变分自编码器）把这些轨道压成一个连续的潜空间 z | 潜空间平滑，相邻 latent 对应相似但连续的动作 |
| 强化学习 | 策略输出"latent 动作 + 12 维辅助动作 + 步态选择"，配合 2Hz 门控 | 策略不用从零发明走路，只需在先验附近微调 |
| 混合控制 | 最终力矩 = 解码器前馈力矩 + PD(默认姿态 + 辅助动作) | 解码器给"计划"，PD 给"稳定"，两层各司其职 |

论文里这些机制全都有效，因为它们的每一个环节都配套：数据带力矩 → 解码器能输出力矩 → 潜空间平滑 →
RL 微调不会离开流形 → aux 在 PD 的"兜底"下做小修正。

### 2.2 我们的替代方案

我们没有论文的 TO 数据和 T VAE，于是做了如下替换：

| 论文环节 | 我们的替代 | 差异 |
|---|---|---|
| TO 数据 | 官方 SONIC 闭环采集的 6.8 万步 token 数据 | 没有力矩、方向分布不均、非周期 |
| TVAE 潜空间 | "相位路由器"（PCA 相位 + 40 个离散原型 token 查表） | 离散的、每命令组一个，不是连续潜空间 |
| 力矩级解码器 | 官方 SONIC 位置 token 解码器（输出 29 关节位置目标） | 输出位置不是力矩，PD 只是跟踪位置 |
| 大规模并行 RL | 先是 MuJoCo 单进程 PPO，后转 Isaac Lab 64 envs | 论文是数千 envs，我们是 64 |

这个"替代管道"从头到尾都成立，但是每一层都缺了论文的配套条件。**这解释了后面几乎所有负面结果。**

## 5. 阶段 0：环境与数据采集（08-11 上午）

### 5.1 环境

- 服务器：`cvgluser@10.16.52.225`，RTX 3060 12GB。
- 数据采集链路：MuJoCo 仿真（`run_sim_loop.py`，**关掉弹性带**）+ 官方 C++ 部署栈
  （`g1_deploy_onnx_ref`：planner → encoder → decoder）。
- 每个控制步（50 Hz）记录：64 维 token、930 维本体感受历史、13 维命令特征。
- 验证：记录的 token 与官方 state logger 完全一致（最大差 0.0），说明采集链路没有丢信息。

### 5.2 一个关键细节：官方链路的 encoder 输出直接喂 decoder

官方链路把 encoder 输出（已经落在 k/16 网格上的值）**直接**喂给 decoder，不再做第二次量化。
我们一开始踩过"二次量化会改变 token"的坑（例如 0.375 会变成 0.3125），后来严格按官方链路走。

### 5.3 评测环境

- `MujocoG1FlatEnv`：无弹性带、aux=0、token 直通官方 decoder。
- **Oracle 控制组**：把官方 token 按相位顺序回放 → 各场景全部稳定（walk vx≈0.8）。
  这证明了评测链路本身是对的——后面所有失败都不是"测试装置坏了"。

**阶段 0 小结论**：

1. 无带环境下官方 token 直接回放就能稳定走路 → 我们蒸馏的上限 = 官方闭环行为；
2. 采集链路正确性已验证，后续所有数据结论可信。

## 6. 阶段 1：蒸馏方案探索（08-11 白天）——"直接学 token"全军覆没

### 6.1 试过的模型（BC 全家桶）

我们把"本体感受 + 命令 → 下一帧 token"当成一个回归问题，试了：

| 模型 | 开环精度 | 闭环表现 |
|---|---|---|
| MLP / 深 MLP / GRU / Transformer（非自回归） | 60–72% | 全部跌倒（3–10 秒） |
| AR（上一帧 token 作输入） | 72% | 跌倒（3–5 秒） |
| AR-delta（teacher forcing 训练） | ~100% | 更差（1–2 秒跌倒）——exposure bias：推理时输入是自己预测的，分布越漂越远 |
| AR-delta + free-run 微调 | – | 仍跌倒（1–2 秒） |

### 6.2 为什么全失败？四个关键发现

1. **token 序列本身高度可预测**：用上一帧 token 预测下一帧，val 精度 93.8%（MSE 0.00025）。
   说明数据里信息是够的。
2. **state→token 的标签是多值的**：官方 planner 的参考相位**不锁**机器人身体相位，每次 1 Hz
   重规划都有独立帧相位。同一个本体状态可能对应多个不同的参考 token。回归模型学的是"条件均值"，
   把相位信息直接抹平了。
3. **闭环复合误差**：开环 val MSE ≈ 0.0012（看起来很好），但一旦闭环运行，token 误差涨到
   0.028–0.039（**放大 20–30 倍**）。注入实验证明：**每 5–10 步必须注入一次正确 token**，
   否则误差累积到跌倒。
4. **解码器对随机误差不敏感**：给 oracle token 随机扰动 8/64 维 ±1 个量化等级，仍然稳定。
   所以失败不是"解码器太敏感"，而是预测误差的**系统性**（都在同一个方向上累积）。

### 6.3 两个"原则上可行"的证据

1. **kNN 记忆蒸馏**：每步用本体感受在训练集里找最近邻（同命令组），输出它的官方 token →
   四种步态 600 步全部存活。这说明 state→token 映射在原则上是可学的，之前的神经网络失败是
   结构/学习问题，不是"数据里没有信息"。
2. **相位是关键单值信号**：官方 token 轨迹做 PCA（64 维压到 2 维）之后，呈现明显的圆形轨迹——
   也就是"步态相位"。相位是单值的（每个时刻只有一个相位角），不像 token 那样多值。

### 6.4 成功的结构：相位回归路由器

最终方案：

1. 每个命令组（mode, speed, 方向）独立一个模型；
2. 对该组官方 token 轨迹做 PCA（64→2），得到圆形步态相位 φ = atan2(第二主成分, 第一主成分)；
3. 把 φ 分成 40 个相位 bin，原型 token = bin 内官方 token 的均值（量化回 k/16 网格）；
4. 小 MLP（930+13 维输入 → 2 维输出）回归 (sin φ, cos φ)，MSE 训练；
5. 推理：MLP → 相位 → bin → 原型 token；对相位做 EMA(0.3) 平滑。

**与 BC 的本质区别**：不回归 token 本身，而是**回归相位 + 查表**。原型是训练流形上的精确点，
闭环不漂移；相位是单值可回归信号，不会被多值标签抹平。

### 6.5 阶段 1 结果（20 秒 × 3 种子）

| 场景 | 完成数 | vx | 位移 |
|---|---|---|---|
| IDLE 站立 | 3/3 | 0.003 | 0.06 m |
| SLOW_WALK | 3/3 | 0.13–0.56 | 2.5–11.2 m |
| WALK | 3/3 | 0.81–0.83 | 16.2–16.6 m |
| FORWARD_JUMP | 1/3 | 0.21–0.84 | ~4.5 m |

40 秒命令切换测试完整通过。

**阶段 1 小结论**：

1. 蒸馏可行，前提是保留"相位"这个周期结构；
2. 直接回归 token = 必死；回归相位 + 查表 = 可行；
3. 跳跃是边缘项（oracle 本身 500 步级也偶发跌倒）；
4. 还缺倒走、转向、横移、连续速度的数据和命令覆盖。

## 7. 阶段 2：补命令覆盖与路由器 v2–v6（08-11 白天到晚上）

### 7.1 补采数据 exp2

新增 32,675 步官方无带闭环数据（**0 次跌倒**），命令覆盖：

- 慢走/行走的**倒走**、**转向**（多角度）、**横移**；
- 更多跳跃（3,756 步）、STEALTH_WALK（2,255 步）。

合并后数据集 `exp_all` = **53,513 步**，5 种模式。路由分组改为 (mode, speed, 方向角 8-bin)，
每个命令组独立一个相位路由器。

### 7.2 迭代中发现的三个问题和修复

**问题 1：合并后 idle 变差（倒走时跌倒）**

- 原因：每段 idle 开头有 1–2 秒由上一步态衰减来的"过渡 token"（段首 token 距离 p90=1.83，
  段中只有 0.11），污染了 PCA 相位和原型。
- 修复：密度离群过滤（每行到组内最近邻 token 距离 ≤ 2.5×中位数）。

**问题 2：评测指标 bug**

- 只测 vx 会把横移/转向误判成"没动"；且转向类命令的朝向应该等于命令方向（fdir=mdir），
  评测里固定 fdir=[1,0,0] 是 OOD 输入。
- 修复：改用 2D 速度/路径指标 + fdir=mdir。

**问题 3：慢走速度退化（合并后慢走几乎站住，vx≈0.01）**

- 定位：exp2 慢走段与 exp1 慢走是**不同节律的步态**（oracle 回放 exp1 vx 0.32 vs exp2
  vx 0.09），混在一起 PCA 相位失效；且 exp1 末段慢走 token 本身在环境里不稳。
- 修复（v5）：慢走组只用 exp1 第一段（4,504 步）→ vx 0.07–0.16，2/3 种子完整。

**阶段 2 小结论（重要，关于"数据质量"）**：

- 相位路由器对"同一命令下不同节律的混合数据"非常敏感——把两种节奏的慢走混进一组，
  PCA 相位直接失效。**数据同质性有时比数据量更重要。**
- 转向/横移能不能走，取决于对应 bin 的官方 token 本身稳不稳。

### 7.3 v5 结果（20 秒 × 3 种子，无带，2D 指标）

| 场景 | 完成数 | 说明 |
|---|---|---|
| IDLE | 3/3 | 0.1 m |
| SLOW_WALK 前进 | 2/3 | 2.2–4.5 m |
| SLOW_WALK 后退 | 3/3 | ~0.9 m（官方后退慢走本身几乎不动） |
| WALK 前进 | 3/3 | 0.83 m/s，16.8–17.0 m |
| WALK 后退 | 3/3 | −0.78 m/s，15.9–16.0 m |
| FORWARD_JUMP | 1/3 | oracle 本身边缘 |
| 右转 60° | 0/3 | ~4 m 后倒 |
| 左转 60° | 3/3 | 几乎不移动 |
| 右横移 | 3/3 | 3.4–3.6 m |
| 左横移 | 3/3 | 几乎不移动 |
| STEALTH_WALK | 0/3 | ~7–9 m 后倒 |
| 58s 命令切换 | 完整通过 | 注意：这个"通过"后来被证伪，见阶段 4 |

## 8. 阶段 3：原型调优（v6）与 DAgger 尝试（v7）（08-11 晚）

### 8.1 原型构造方式扫描（v6）

对边缘分组扫描"原型构造方式 × 相位 bin 数"（mean/median/nearest × B=40/64）：

| 分组 | 最佳配置 | 效果 |
|---|---|---|
| 跳跃 | median, B=40 | 1/3 → **3/3 完成** |
| 右转 60° | mean, B=64 | 2/3 → **3/3 完成** |
| 左转/左横移 | nearest, B=40 | 从"站立不动"→ **3/3 且真正移动**（路径 0.3–10 m） |

最终 v6（= distill_final）完整结果：除 STEALTH 外全部 3/3，STEALTH 与 oracle 持平
（官方 stealth token 回放也在第 361 步跌倒——**教师上限**，不是蒸馏缺陷）。

### 8.2 DAgger 尝试（v7，未采用）

对慢走做了 1 轮 DAgger-lite：用 v6 慢走路由器闭环 rollout 收集 2,543 个学生状态，用 kNN
（最近官方慢走状态）的 PCA 相位作标签重训相位网络。

结果：慢走从"2/3 完成、vx 0.08–0.23"**退化**为"3/3 完成但 vx≈0.01（站住不动）"。

**小结论**：kNN 相位标签在慢走这种**弱节律步态**上偏向保守均值，收益为负。弱节律步态需要
更干净的参考标签（如真实 planner 相位）或 RL 辅助，单纯加闭环状态重标注不够。

### 8.3 阶段 3 总结论（蒸馏可行性的终版）

1. 一个小型神经网络（14 个命令组相位路由器，每组 ~0.5M 参数）从 53,513 步官方无带闭环数据
   蒸馏而来，可在 MuJoCo 无带条件下稳定完成：站立、慢走（2/3）、前进/倒走行走（3/3，速度与
   官方一致）、跳跃（3/3）、转向/横移（3/3）、58s 命令切换。
2. 上限由三部分构成：
   - **教师上限**：stealth 官方 token 本身不稳（361 步倒），蒸馏无法超越老师；
   - **数据同质性**：混合节律会破坏相位（慢走案例）；
   - **BC 回归硬上限**：直接 token 回归的闭环复合误差（每 5–10 步需纠正）无法绕过。

## 9. 阶段 4：单模块封装与压力测试（08-12 早）——"58s 通过"是假象

### 9.1 单一 encoder 模块

把整个路由器封装成 `PhaseRouterEncoder`：统一接口 `encode(Command, proprio_history) → 64-d
token`，内部自动完成组选择（含回退）、PCA 相位推理、原型查表、EMA 平滑、组切换时重置 EMA；
`Command.from_vxvy` 把线速度命令映射到官方命令空间。压测全程通过该模块驱动，与内联评测一致
（vx 0.83、60s 50.9–52.0 m），验证了模块与评测实现等价。

### 9.2 压力测试结果（无带 MuJoCo）

**A. 连续直线行走 60 秒 × 3 种子：3/3 完成**（vx 0.83–0.85，位移 50.9–52.0 m）。

**B. 行走中扰动冲击（200/500 N，4 方向 × 3 种子 = 24 组）：21/24 完成**

- 绝大多数冲击后 0.02–2.6 秒内恢复；3 组失败是种子依赖的边缘情况，且跌倒发生在更晚时刻
  → 单次扰动不是问题，复合应力下的边缘状态才是。

**C. 68 秒命令切换马拉松 × 3 种子：0/3 完成** —— 都在中后期跌倒（2 个种子在跳跃阶段，
1 个在 walk_back 阶段）。

**重要修正**：此前"58 秒命令切换通过"是 env 默认 episode_length=20 秒的假象
（1000 步即终止并复位）。用正确 episode 长度重测后，多命令连续运行的真实上限约为
**35–40 秒，瓶颈在跳跃**（及个别 walk_back 转换）。

### 9.3 阶段 4 小结论

1. 单命令连续运行（前进/倒走）60 秒+ 稳定，位移约 50 m；
2. 行走中 200–500 N 冲击基本可吸收并恢复；
3. 多命令连续切换是真实上限所在：长时间运行后进入跳跃是最脆弱的环节；
4. 修复方向：跳跃的长时上下文鲁棒性需要真实 planner 相位监督的 DAgger，或 RL 微调
   （此前 kNN 近似标签的 DAgger 已证无效）。

## 10. 阶段 5：MuJoCo 按论文两条线补 RL（08-12 白天）——基础设施不足，判定无法继续

按论文把实验拆成两条线：

### 10.1 控制器线：冻结相位路由器 + PPO 训练 aux

环境新增 `phase_router`（冻结 token 先验）：策略不直接输出 token，而是输出 12 维 aux 叠加在
下肢关节上；评测 A=60s 行走、B=500N 扰动、C=68s 命令切换、D=跳跃。

试了 7 个 RL 变体（aux-only × 4、phase+aux × 3），结果**全部劣于 aux=0 的蒸馏先验**：

| 变体 | A 60s | 结论 |
|---|---|---|
| noaux（基线） | 3/3（50.8–52.0 m） | 基准 |
| aux 原始 | 0/3 | aux 有害 |
| aux C1（低熵） | 0/3 | aux 有害 |
| aux C2（+扰动课程） | 0/3 | 扰动课程无效 |
| phase+aux 联合 RL | 0/3 | 联合 RL 无效 |
| aux C3（4 并行 env） | 收益崩塌 | 多 env 仍无效 |

训练收益早期能到 110–127（说明短回合内 aux 能配合），但评测中 aux 均导致长时/扰动/切换下
更快跌倒（vx 从 0.83 降到 0.2–1.0）。

**判定**：单进程 MuJoCo PPO 样本效率不足，无法像论文（数千并行 env）那样学到稳定闭环修正。
控制器线停止，原因 = 并行 RL 基础设施缺失。

### 10.2 数据线：闭合周期 token 数据集

用户提过一个很关键的问题：APT 论文里动作拆成循环，首尾应该能连上；但我们蒸馏用的数据看起来
连不上，会不会越走越偏？于是我们把数据线做成了"把原型闭合"：

- 每命令组：PCA 圆相位 → 40 bin 均值周期 → 末 8 bin 线性缝合回 bin0；
- 闭合判据：`||μ[B-1] − μ[0]||` 从 0.04–1.38 降到 **0.00000（全部 14 组）**。

复测结果：

| 测试 | 原始路由 | 闭合路由 |
|---|---|---|
| A 60s 行走 | 3/3 | 3/3（持平） |
| B 扰动 500N | 10/12 | 8/12（略差） |
| C 68s 切换 | 2/3 | 0/3（更差） |
| D 跳跃 | 2/3 | 2/3（持平） |

另外还试了"相位 AR"（把上一帧预测相位也喂回网络）：同样更差（A 1/3）。

**这是对用户问题的直接回答：** 闭合判据达成（0.00000）**但没有改善闭环鲁棒性**。
漂移不是由"原型回绕不连续"引起的，而是由"控制器层缺参考重锚定/闭环修正"引起的。
合成闭合 token 与真实状态分布有轻微不一致，反而在扰动/切换场景引入更多误差。
**所以"数据首尾连不上"不是问题根源；问题根源在控制器层没有闭环修正。**

### 10.3 阶段 5 最终结论

- 控制器线：判定无法继续（缺并行向量化 RL 基础设施）；
- 数据线：判据达成但目的未达成（闭合先验无法替代闭环机制）；
- 换平台：切换 Isaac Lab（RTX 3060 12GB），按论文路线继续。

### 11.4 每个变体的机制结论（按实验顺序）

**E1 基线**：Isaac 下冻结路由器闭环与 MuJoCo 一致（A 47 m vs MuJoCo 51 m，B/C/D 全过，Isaac
甚至更稳）。随机 aux 行（无训练）位移掉到 27.6 m——说明 aux 通道确实影响行为。

**E2（aux + naive 2Hz 门控）**：训练收益平稳 ~1.8、500 iters 零摔倒，但评测位移只有 3–11 m
（严重偏航漂移），跳跃速度下降。**结论：无扰动压力时 PPO 学到的 aux 不是增益修正，而是把先验
行为带偏。**Isaac 并行 RL 解决了"学不到稳定闭环"，但平坦低扰动下 aux 没有正向收益。

**E4（aux + 扰动课程）**：扰动 0→0.35 ramp。结果位移 1.96–3.55 m，漂移比 E2 更重。根因假设：
奖励缺 aux 幅度/速率正则，且 track_yaw 的 σ²=0.25 过宽，慢速旋转几乎无代价。

**E7 作废 → E7b**：E7 的扰动语义错了（每步 35% 概率推力，远严于 MuJoCo 的"每回合一次单步推力"），
收益被压到 0.9–1.2，作废。修正语义后的 E7b（+aux 正则 + 紧偏航）在 600 iters 时 **0/3 全倒**。

**E3 系列（phase+aux 联合 RL）**：策略直接输出相位。无 EMA → KL 爆到 10、策略漂移；+EMA → vx≈0.04
站立偷懒；+紧速度奖励 → vx≈0.07 仍不走路。**机制性结论：离散相位 bin 选择 + MLP PPO 无法学会
"推进步态相位"——恒定相位 = 静态姿势。**这正是论文用 TVAE 连续潜空间的原因：解码器流形天然平滑、
时序连贯；SONIC 的离散 token 空间没有这个结构。

**E6（门控消融）**：关掉 naive 2Hz tick 后，aux 破坏性大幅下降（位移 16–32 m vs 3–11 m），
跳跃速度反而超过 noaux（0.75 vs 0.68）。**结论：我们 naive 实现的自由运行 2Hz 布尔信号被策略
当作时钟源，诱发周期性 aux 干扰；论文的 2Hz 信号绑定步态决策，与我们的实现不等价。**

**E8（phase warm-start）**：前 150 iters 用路由器相位做 MSE 监督（系数衰减），从"能走"开始
RL 微调。早期 vx 0.20→0.28 爬升，it_300 评测 3/3（vx 0.99 超速，位移 7–19 m），B/C/D 全过。
结论：warm-start 能注入行走，但 RL 微调后期退化（超速+漂移）。

**E9/E11（vanilla RL，无先验）**：800 iters 和 2000 iters（2.5 倍算力）全部 0/3 立即摔倒。
**蒸馏先验的必要性得到直接证据：同等预算无先验 RL 完全无法行走。**

**E10（aux 轻正则）**：即使加轻正则（aux-l2 0.005），仍超速+偏航漂移。漂移是该奖励/动作空间下
aux 的稳健行为，与正则强度关系不大。

**E12（aux scale 缩小 4 倍）**：漂移与 aux 幅度关系不大——即使缩小权限，策略仍用持续的小幅
关节修正造成慢速偏航累积。

**E13（修正版 2Hz 门控）**：门控布尔信号只在"路由器组切换"时置 1（决策绑定），组选择在 2Hz 边界
评估并保持 0.5s。训练收益全程稳定（无 E2/E6 后期退化），A 位移 **34–37 m**（基线 47 m 的 ~78%），
但 D 跳跃速度下降（0.44 vs 0.68）。**这是论文门控机制的正向验证：按正确语义实现后，漂移显著减少。**

**E14（修正门控 + 扰动）**：加扰动后位移掉到 5.7–12.6 m——扰动压力下 aux 的漂移再次放大，
无法转化为正向收益。

### 11.5 阶段 6 最终结论（Isaac 平坦地面）

1. **蒸馏先验必要**：冻结相位路由器（aux=0）全项最优（A 47 m、B/C/D 全过）；同等预算 vanilla
   RL 无法行走（E9/E11 立即摔倒）。
2. **aux 在平坦地面无正向收益**：全部 learned-aux 变体存活率达标但超速+偏航漂移；与论文逻辑
   一致——aux 的价值在"先验覆盖不到的工况"（地形/强扰动），平坦地面 aux=0 最优。
3. **phase/latent 线需要结构化潜空间**：离散 token 相位不具备论文 TVAE 的时序平滑性。
4. **实现偏差记录**：naive 2Hz tick 与论文的"步态决策绑定信号"不等价；修正后（E13）有正向证据。

## 12. 阶段 7：地形 / 感知 / 动作通道 E15–E21b（08-12 白天到夜）

### 12.1 先修一个"坑中坑"：地形生成的可复现性

- 一开始 `TerrainGeneratorCfg.seed` 无效：Isaac 内置 `HfRandomUniformTerrainCfg` 的高度场用
  **全局 np.random**，与生成器局部 rng 无关。不同进程生成不同地形 → 0.08 比 0.10 更差的非单调
  结果无法归因。
- 修复：在创建 env 前显式 `np.random.seed(terrain_seed)`。修复后 0.06 s0 两次 noaux 均为 3/3。
- 附带修复：reset 根高度改为 `env_origins + 0.76 + jitter`（修复脚插地）、`reset_grace_steps=25`
  （修复 reset 碰撞早期误判终止）。

### 12.2 先验盲走鲁棒性曲线（冻结路由器，无 RL，固定 seed 0，60s，vx=0.8）

| noise | 完成 | 说明 |
|---|---|---|
| 0.04 | 3/3 | vx 0.76–0.78，44.6–47.0 m |
| 0.06 | 3/3 | vx 0.73–0.76，40.6–44.2 m |
| 0.08 | 1/3 | 约 29–41 秒跌倒 |
| 0.10 | 0/3 | 6.5–29 秒跌倒 |

**结论：先验盲走能力悬崖在 0.06→0.08 之间。这正是 aux 理论上应该发挥作用的地方。**

### 12.3 E15：盲 aux + 地形课程（无感知）

0.04→0.06→0.08 课程训练，评测：

| noise | aux | noaux |
|---|---|---|
| 0.04 | 3/3（vx 0.40–0.43，3.7–11 m） | 3/3（vx 0.76–0.78，42–46 m） |
| 0.06 | 2/3（vx 0.43–0.48，1.7–9.7 m） | 3/3（vx 0.71–0.78，36–46 m） |
| 0.08 | 0/3 | 0–1/3 |

**结论**：纯 proprio 的 aux 在粗糙地形上无正向价值——它把速度砍半，悬崖噪声下 0/9 完成。
论文中 aux 的正向案例（越障、断腿补偿）依赖 elevation map 感知；**无感知时 aux 只是反应式
拐杖，不能提前修正落脚**。

### 12.4 E16：aux + 特权 elevation map

实现：9×9 @0.15m 局部地形块（随 yaw 旋转，相对根高度）加入观测。

| noise | E16 aux（+地图） | E15 aux（盲） | noaux |
|---|---|---|---|
| 0.06 | **0/3** | 2/3 | 3/3 |
| 0.08 | **0/3** | 0/3 | 0–1/3 |

**结论（负面但精确）**：把特权地图接进策略后 aux 没有变好，反而在 0.06 变差。原因不是"地图
没用"，而是**我们只有 aux 动作通道，地图没有可表达的载体**——论文中 elevation 的价值通过
latent 动作 + gait logit（改变整身计划/步态选择）传导，而我们的相位路由器和相位头是冻结/哑的。

### 12.5 E17 / E17b：策略学习步态选择（gate）+ elevation + 进度奖励

策略输出 12 维 aux + 3 选 1 组选择（idle/slow_walk/walk_fwd），2Hz 决策绑定。

| 变体 | 0.06 | 0.08 |
|---|---|---|
| E17 aux | 0/3（反向移动后倒） | 0/3 |
| E17 noaux（gate，aux=0） | 3/3 但 vx≈0（站住） | 3/3 但 vx≈0（站住） |
| E17b aux（+progress） | 0/3 | 0/3 |
| E17b noaux | 3/3 但站住 | 3/3 但站住 |

**结论（负面但揭示机制）**：给策略组选择通道后，最小化奖励下它学会"站住"来规避摔倒。
进度奖励能防止"站住"，但无法让 aux/gate/elevation 组合在粗糙地形稳定行走。**论文的步态选择
机制依赖"必须前进"的任务/奖励设计**，我们的最小奖励允许 idle 坍缩。

### 12.6 E18 / E19 / E19c：phase 直控与相位锚定

**E18（phase 直控）**：策略输出相位（warm-start 150 iters 后衰减）。训练期能走（vx 0.5–1.1），
但闭环粗糙地形 0/3（0.06 在 100–125 步倒）。结论：warm-start 衰减后策略相位偏离路由器精确相位。

**E19（全程相位锚定）**：相位 MSE 监督全程保留（1000 iters、系数 2.0 线性衰减但不归零）——
策略只能在路由器相位流形附近微调。

| noise | phase+aux | phase-only（aux=0） |
|---|---|---|
| 0.06 | **3/3 存活**（vx −0.06，倒走漂移） | 3/3 存活（站住） |
| 0.08 | **3/3 存活**（vx −0.05，倒走） | 3/3 存活（站住） |

**关键发现**：相位锚定后，学习策略首次在 0.06/0.08 达到 3/3 存活——抗倒性超过冻结先验
（0.08 先验仅 0–1/3）。但代价是丢失前进运动（倒走/站住）。**"存活 vs 任务"权衡再次出现：
最小奖励下策略选择不倒而非前进。** 先验流形约束是 learned 组件能存活的关键——这佐证了论文
"latent 动作 + 冻结 decoder"设计中先验约束的必要性。

**E19c（+aux 正则）**：aux 正则把 E19 的 3/3 存活打回 0–1/3——E19 的大幅 aux 确实在承担地形
稳定（代价是倒走），限制它反而破坏存活。

### 12.7 E20 / E20c：anti-stop 方向压力与 gate-only 的转折

**E20（phase 锚定 + anti-stop）**：奖励新增"vx<0.3 时惩罚"。结果：平坦下超速画圈（位移仅
1.8–3.5 m）、rough 0.04 超速跌倒、0.06 全倒、0.08 爬行。**速度/存活冲突，无甜点。**

**E20c（gate + anti-stop，阈值降到 0.1）**：让策略有动机选"慢走前进"组而非 idle。

| 场景 | gate+aux | gate-only（aux=0） |
|---|---|---|
| rough 0.06 | 0/3（倒走） | **3/3，vx 0.71–0.77，38–43 m** |
| rough 0.08 | 0/3 | 0/3（seed2 活到 2953 步 ≈ 59s） |

gate-only 全量评测：平坦 B 12/12、C 3/3、D 3/3、A 3/3；rough 0.06 B 10/12、C 3/3、D 3/3。
跨地形扩展：rough 0.06 三地形 seed **9/9 全部前进存活**（38–45 m）；0.08 0/9 完成但存活
21–59 秒（= 先验边缘区，无增益无损失）。

**结论升级（这是整个 Isaac 阶段最重要的正面结果）**：

1. **可学习的步态选择（gate）在正确奖励压力下是"无损"的**——它收敛到选择先验自己的最优组；
2. **破坏性始终来自 aux 通道**——从 E2/E6/E10/E12/E15 到 E20c，任何学习到的 aux 修正都让先验
   退化（超速/偏航/倒走/跌倒）；
3. 论文中 aux 的正向价值需要力矩级解码器（PD 稳定下的力矩修正），SONIC 位置目标 + 关节偏移的
   替代无法复现。

### 12.8 E21a：gate + anti-stop + 特权地图（把地图给 gate 通道）

把 elevation map 从 E16 的 aux 通道移到策略观测（含 gate 通道），rough 0.06 训练。

| 场景 | gate+aux（E21a） | gate-only（E21a） | 对照 E20c gate-only |
|---|---|---|---|
| rough 0.06 A60s | 2/3 完成，vx 0.13–0.14（慢走 5–7 m） | **3/3，37–43 m** | 3/3，38–43 m |
| rough 0.08 A60s | 0/3 | 0/3 | 0/9 完成 |

**结论**：

1. 地图+gate 让 gate+aux 从 0/3 倒走变成 2/3 慢速前进（地图缓解了 aux 的破坏），但没有产生
   正向价值，仍远差于先验；
2. **特权地图不能突破 token/解码器流形上限**：策略没有"地形对应的新行为"可学（流形里只有
   idle/slow/walk 原型），地图信息无处传导；
3. 这进一步收敛方向：**感知（地图/深度）不是当前管道的瓶颈；动作流形（力矩/新步态）才是。**

### 12.9 E21b：先验在离散地形（台阶/垫脚石/障碍）的直接评测

意外正向：**小台阶（4–8 cm）在先验能力内**——walk 原型本身带小障碍跨越能力：

| 地形 | A60s 结果 |
|---|---|
| stairs（0.04–0.08m 阶高，0.35m 阶宽） | **3/3 完成，vx 0.30–0.36，18–22 m** |
| stairs_hi（0.08–0.14m） | 待测 |
| stones / discrete | 待测 |

这修正了"先验完全不含地形行为"的说法：**粗糙地形不行，但小离散台阶可以。**

## 13. 阶段 8：数据/网络泛化实验（08-12 白天）——"更好的数据/网络"试了个遍

这个阶段回答的问题："是不是数据不够？是不是网络不够好？换更好的网络能不能泛化到没见过的方向？"

### 13.1 数据覆盖量化（exp_all，53,513 步）

| mode | 含义 | 步数 | 方向覆盖 |
|---|---|---|---|
| 0 | IDLE | 14,456 | 仅一个方向 |
| 1 | SLOW_WALK | 19,534 | 8 个方向 bin 全有，但**极不均衡**：bin4=9500、bin0=5231、bin1=1701、bin5=1634、bin2=704、bin6=470、bin3=164、bin7=130 |
| 2 | WALK | 11,259 | **只有前进（9006）和倒走（2253）** |
| 17 | FORWARD_JUMP | 6,009 | 仅前进 |
| 18 | STEALTH_WALK | 2,255 | 仅一个方向 |

cmd vx 覆盖全部在 0–1.0（无负向高速、无 walk 级侧向/斜向）。**路由器按组建模，unseen
方向只能 fallback 到最近组——这就是泛化缺口的直接来源。**

### 13.2 v8：单一共享相位网络（负面结果）

设计：一个共享 MLP 覆盖全部 14 组（proprio+cmd → 相位），加一个共享 token 解码器
（相位+cmd → token）。

结果：共享相位网络 per-group 相位角误差 **0.85–2.29 rad**（对比 v6 的 ~0.001–0.016 rad，
退化约 100–1000 倍），闭环全场景失败。

**结论：proprio→phase 映射强分组相关，不能简单共享；相位阶段必须保留 per-group 结构。**

### 13.3 v8c：per-group 相位 + 单一共享 token 解码器（部分成功，总体不优于 v6）

相位仍用 v6 的 per-group MLP（~0.005 rad 精度）；token 由单一解码器生成（相位+cmd → 64-d）。
unseen 命令走"fallback 组相位 + unseen cmd 输入解码器"，连续插值而非离散跳组。

| 场景 | v6（原型 fallback） | v8c（共享解码器） |
|---|---|---|
| walk_fwd | 3/3，16.9 m | 3/3，16.3 m |
| walk_back | 3/3，−16 m | **0/3**（~3.5s 倒） |
| 转向/横移 | 3/3 | 大多 0/3 |
| unseen 斜向 bin | 3/3（走成前进） | bin5 3/3、bin7 2/3、其余 0/3 |

**结论**：连续解码器输出的 token 不是训练流形上的精确点，闭环误差累积（与 BC 回归失败的机制
同源）；v6 的离散原型 + fallback 反而更稳——**fallback 至少把命令"降级"成已学过的稳定步态**。
顺带发现：**倒走对 token 扰动更敏感**，是后续任何连续/潜空间方案的更严测试项。

### 13.4 exp3 补采 + v9 重建：数据补全了，但没有突破

用 planner 键盘驱动补采 walk 6 个缺失方向（左右旋转扫描 + 横移 + slow 速度变化），新增
14,580 步，**0 次跌倒**。合并后 exp_all3 = 68,093 步，walk bin1–3/5–7 全部补上。

v9 重建结果：

| 场景 | v9 结果 | 对比 |
|---|---|---|
| walk_fwd / walk_back | 3/3 | = v6（倒走略慢） |
| idle / slow_back / turn / strafe | 3/3 | = v6 |
| jump | 2/3 | v6 3/3，轻微回归 |
| stealth | 0/3（比 v6 多活 ~150 步） | 教师上限内 |
| walk_bin5（+45°） | **3/3（走成前进 16.8 m）** | 比 oracle 稳 |
| walk_bin1/2/3/6/7 | 0/3（3–10 秒倒） | 见 oracle 上限 |

### 13.5 oracle 上限检查：官方 token 直接回放 6 个新方向（本次核心问题的直接证据）

| 方向 bin | 跌倒步数 |
|---|---|
| bin1 | 216 |
| bin2 | 270 |
| bin3 | 144 |
| bin5 | 95 |
| bin6 | 177 |
| bin7 | 137 |

**全部在 95–270 步（2–5.4 秒）内跌倒。教师（官方 SONIC token + 本 MuJoCo 环境）本身做不了
稳定的 walk+turn。**

**阶段 8 结论（对"要不要更好的数据/网络"的完整回答）**：

1. 数据覆盖是必要不充分：补全方向后闭环稳定性没有突破，瓶颈是 SONIC token 流形 + 本环境的
   walk+turn 上限（教师本身不行）；
2. v9 在 bin5 把斜向命令"降级"成前进（3/3 稳定），bin3/7 比 oracle 多活 2–4 倍——**降级到
   稳定步态是比直接执行教师不稳定行为更优的泛化**；
3. 网络侧：普通回归解码器（v8c）会离开流形；离散原型 + fallback（v6/v9）更稳；要超越上限需
   换带力矩标注的数据 + 力矩解码器（论文原方案）或换环境（Isaac 已验证更宽容一点但同样的悬崖）。

### 13.6 TVAE-lite：论文表示学习的直接类比（负面结果）

实现：encoder(proprio, cmd) → z∈ℝ16；decoder(z, cmd) → 64-d token；loss = 重建 MSE + β·KL
（β 0→0.1 退火防后验坍缩）。

结果：

- **KL 后验坍缩**：退火后 val_kl → 0（z 被正则压成先验，信息归零）；最终模型重建误差 0.0088
  （远差于 v8c 的 0.00076）——高容量 cmd 条件解码器可以基本忽略 z，相位变化作为小残差被 KL 杀掉；
- 最佳 checkpoint（β 小时保存）闭环评测：walk_fwd 0/3（200–251 步倒），walk_back 0/3，
  slow 1/3，idle 3/3，其余 0/3。

**结论（网络泛化的完整证据链）**：

1. 三种"更好的网络"全部失败：共享相位回归（v8）、显式相位+共享回归解码器（v8c）、VAE-lite
   学习潜空间（本实验）。失败机制：朴素回归离开 token 流形（闭环误差累积）；KL 正则导致后验
   坍缩（相位信息被压掉）；
2. 现有最优结构仍是 v6/v9：**显式 PCA 相位 + 离散原型查表**——原型是训练流形上的精确点，
   闭环不漂移；
3. 论文 TVAE 之所以有效，是因为 (a) 解码器输出**力矩**（PD 稳定，容忍小幅 latent 误差），
   (b) TO 数据的物理结构让潜空间干净。我们的 SONIC 位置 token 解码器 + 多值标签不满足这两个
   条件——**这不是"我们没做对"，而是替代管道的固有上限。**

### 13.7 开源实现实证（unitree_rl_mjlab 源码核对）

核对 Unitree 官方 G1 velocity tracking 配方，发现主流做法是：

- **地形感知**：raycast 高度扫描网格（1.6×1.0 m，0.1m 分辨率）直接进 actor 与 critic；
- **显式 phase 观测**（period 0.6s）——与我们的"相位路由器"思想一致；
- **丰富奖励**：pose/body_orientation/foot_clearance/foot_slip 等 task+style 项（我们只有 5 项
  最小奖励，E17 的 idle 坍缩正是缺"必须前进"任务压力的直接后果）；
- **并行**：默认 4096 envs（我们 64）；
- **命令**：lin_vel_x ∈ [−0.5, 1.0]、lin_vel_y ∈ [−0.5, 0.5]、ang_vel_z ∈ [−0.5, 0.5]
  （比我们的 vx∈[0,0.8] 宽）。

**对照结论**：主流 G1 速度 RL 配方 = 地形高度扫描进策略 + 显式 phase + 丰富奖励 + 千级并行。
我们逐项复现了地形感知（E16）与相位（v6/v9），但奖励与并行规模不足、动作通道受限——E15–E18
的负面结果与官方配方逐条对应，**差异在工程条件而非机制理解**。

## 14. 阶段 9：MuJoCo 粗糙地形 + 力矩级解码器（08-12 夜）——两个"最后一个问题"的答案

### 14.1 MuJoCo 本地粗糙地形（hfield）——"凹凸不平的地面怎么实现的？和论文像吗？"

实现方式：MuJoCo 3.11 高度场（hfield）。40×40 m @0.1m 分辨率，0.4m 粗格均匀 ±amp，σ=1.2
高斯平滑，中心 0.4×0.4m 铺平（出生点）。**没有坡度上限**，所以同一标称振幅比 Isaac 的
`HfRandomUniformTerrainCfg`（slope_threshold=0.75）更陡。

修了两个坑：

1. `elevation` 属性是**内联数字列表**不是文件名；二进制地形要用 `file="xxx.bin"` + MuJoCo
   二进制格式（int32 nrow/ncol 头 + float32 数据）；
2. `size=(x,y,z,base_z)` 的 base_z 不参与碰撞：碰撞面 = `geom.pos.z + size[2]×data`，所以
   geom pos z 必须设成 hmin。**修复前机器人直接穿地（ncon=0），早期"全倒"是伪结果。**

坡度统计（seed 0）：amp=0.02 时 p99 坡度 ≈ 0.078；amp=0.03 → 0.118；amp=0.04 → 0.157；
amp=0.06 → 0.235；amp=0.10 → 0.392（28.4°）。

鲁棒性曲线（walk 前进，1000 步 = 20s，3 seeds）：

| amp | v9 walk | v6 walk |
|---|---|---|
| 0.00 | 3/3，15.9–16.0 m | 3/3 |
| 0.02 | 3/3，16.5–16.8 m | 3/3 |
| 0.03 | 2/3 | 3/3 |
| 0.04 | 0/3（4.1–14.7 m） | 0/3 |
| 0.06 | 0/3 | 1/3 完成 |
| 0.08 / 0.10 | 0/3 | 0/3 |

**结论**：

1. 本地地形阈值 ≈ amp 0.02–0.03；Isaac 同标称是 0.04–0.06。但**按坡度对齐后两者阈值一致**
   （本地 0.02–0.03 的 p99≈0.08–0.12 与 Isaac 0.06 相当）——差异来自地形生成参数（无坡度
   上限），不是控制器或平台能力问题；
2. 失败模式：不是立即倒，而是先以 0.8–0.9 m/s 走出 3–5 m，然后在小凸起/下陷上绊倒
   （h_min≈0.2），与 Isaac 失败模式一致；
3. idle（零 token）在平地就缓慢漂移并在 ~17–19 秒绊倒——**零 token 不是真正的驻留控制器**，
   只适合当"站住"的弱基线；
4. 论文中的地形用的是 7 类程序化地形（粗糙、台阶、垫脚石、障碍等）+ 课程，我们实现了粗糙 +
   离散台阶（E21b），方向一致但规模小得多。

### 14.2 力矩级解码器实验——"为什么 aux 永远是负面的？"的机制根源

论文的混合控制是 τ = τ_dec + PD(q_default − q + aux)，解码器输出**力矩**。我们的替代管线里
解码器输出**位置**。这看起来只是形式差异，其实是本质差异。为了验证，我们做了最直接的测试：

**步骤 1：从闭环 PD 力矩标签恢复"力矩先验"**

用 `tau = kp×(q_des − q) − kd×q̇` 离线重算 PD 力矩（前 12 个下肢关节），训练 phase+cmd → 力矩
的 MLP。结果 val RMSE 18.76 N·m（≈ 预测零的水平）。

**解释**：闭环 PD 力矩主要由**瞬时跟踪误差 (q_des−q)** 决定，相位+命令只能预测其周期均值；
这个 RMSE 就是不可约的反馈分量，不是拟合失败。

**步骤 2：MuJoCo 闭环评测**

| 控制方案 | 平坦 walk | 粗糙 0.06 walk |
|---|---|---|
| baseline（token 位置路径） | 3/3，15.8–16.0 m | 0/3 |
| 论文式（tau_dec + PD(默认位姿)） | **3/3 存活 20s 但 vx≈0.03（站住不前进）** | 1.2–1.6s 倒 |
| 混合式（token PD + tau_dec 前馈） | 1.3–1.5s 倒 | 1.3–1.5s 倒 |

**最终结论（这条线判定为死路）**：

1. 纯论文式能**稳住不倒**，但产生不了行走——步态的位置模式来自 token 路径；相位条件均值力矩
   缺乏"规划性"（没有触地反力/摆动时序的计划成分）；
2. 混合式把反馈力矩当正向力矩叠加 = **双倍反馈，直接失稳**；
3. **从闭环 PD 力矩恢复"力矩先验"在原理上不成立**。要复现论文的 aux 正向价值，需要真正的
   轨迹优化（TO）或逆动力学生成的前馈力矩数据，而不是记录 PD 力矩。

**这解释了 E2–E20c 所有 aux 负面结果的共同根源：替代管道里"力矩通道"这一层缺失，且无法用
PD 标签廉价补上。**

## 15. 综合结论（机制层，回答"为什么"）

### 15.1 为什么官方 SONIC 生成不了某些动作（walk+转向/横移）的长效数据

这是本次研究的核心问题，答案分三层：

**第一层：SONIC 本质上是一个短时程闭环跟踪器，不是长时程动作生成器**

- 官方论文（arXiv 2511.07820）：控制策略的编码器输入是未来 10 帧（约 200ms）的参考运动
  （teleop 模型只有 4 帧/80ms），配合当前本体状态；
- 它每次决策依赖"当前状态 + 眼前 200ms 的参考"，是一个 Markov 化的跟踪器；
- 官方"长效"动作靠 kinematic planner 兜底：**每 100ms 重新生成 0.8–2.4s 的运动段**，且
  "continually regenerates future kinematic motions conditioned on the previous robot states
  and incoming user commands"（根据之前的机器人状态和用户命令持续重新生成未来运动）；
- 官方 MuJoCo 模拟里还有 ElasticBand（一根 kp=10000 的虚拟弹簧把骨盆拉向 `[0,0,1]` 固定点）
  兜底；
- 论文自己的 Limitations 也承认 extended deployments（长时部署）的安全、顺服、能效没有正式
  处理，future work 要联合训练 planner/tokenizer/policy 来 reduce modality gaps（减少模态间隙）。

**第二层：我们蒸馏时把两个闭环都拿掉了**

- 官方闭环链：`encoder(当前本体状态 + 未来参考) → token → decoder → PD 目标`，每一步本体
  状态都反馈回 encoder，误差会被重编码纠正；
- 我们的蒸馏链路：`预存 token 流 → decoder → PD`，本体状态**不参与生成 token**；
- 去掉 ElasticBand + 去掉 planner 重规划 + 去掉 encoder 状态反馈，就只剩"开环重放"。
  任何跟踪误差都会累积：开环 token 误差 ≈0.0012，闭环涨到 0.028–0.039（20–30 倍），
  每 5–10 步必须注入一次正确 token。

**第三层：FSQ 有损瓶颈 + 数据方向覆盖不均**

- SONIC 用 FSQ（Finite Scalar Quantization，64 维离散 token）做有损瓶颈；
- 数据（BONES-SEED，142K+ 人类运动片段）以直行/跑步/舞蹈为主，转向/横移方向天然稀少
  （我们本地数据里 slow-walk 的 bin4=9500 条 vs bin7=130 条，差 70 多倍）；
- 稀有方向在 token 空间里覆盖薄，量化后邻近 token 解码出的轨迹"相似但错误"，误差一步步复合；
- 实证：官方 token 直接回放 6 个新方向 walk，全部在 **95–270 步**内跌倒。

**所以：官方 SONIC 的"长效数据"只有两种合法来源——保留 planner 闭环重规划（每 100ms 重规划 +
状态反馈），或换真 TO/逆动力学力矩数据。把官方 token 流开环重放，天然只能得到短片段。**

### 15.2 为什么 APT 论文"覆盖得到"而我们覆盖不到

| | APT 论文 | 我们的 SONIC 替代 |
|---|---|---|
| 数据来源 | TO 自己生成：2D 周期轨道 + 力矩，−2~7 m/s 全覆盖 | 人类运动库有限分布，方向不均，无力矩 |
| 物理结构 | 干净、周期、自带前馈力矩 | 位置级参考，无规划力矩 |
| 潜空间 | TVAE 连续平滑 | 离散 token / 相位 bin |
| 解码器 | 输出力矩（PD 稳定，容忍误差） | 输出位置（off-manifold 敏感） |
| 并行 | 数千 env | 64 env（RTX 3060） |

一句话：**论文按"我定义什么命令，就生成什么数据"来；SONIC 按"数据里有什么，才能跟踪什么"来。**

### 15.3 整条替代管道的最终判词

1. **蒸馏先验（冻结相位路由器 + SONIC 解码器）是当前管道最优控制器**：平坦全项通过、60s 前进
   47–52 m、粗糙 0.06 盲走 3/3、小台阶 3/3；
2. **论文的 aux / elevation / 步态选择机制在逐一补齐后均未带来正向价值**，根因是替代管道缺少：
   力矩级解码器、结构化连续潜空间、千级并行、强制任务奖励——这正是论文与主流开源实现
   （unitree_rl_mjlab）的生效条件；
3. **唯一的"学习不破坏先验"组件是 gate（步态选择）+ anti-stop 训练（E20c）**——它无损且跨
   地形 9/9 前进；
4. 突破上限需要换硬件/数据/解码器条件，而不是在当前管道里继续加组件。

## 16. 对你之前所有问题的逐条回答（说人话版）

### 16.1 蒸馏是必要的吗？

**必要，而且是最优路线。** 同等预算的 vanilla RL（无先验，800/2000 iters）0/3 立即摔倒；
先验版 800 iters 内全项通过。蒸馏先验的样本效率优势是数量级性的。成本也最低（小 MLP，不需
大规模并行 RL）。

### 16.2 我们之前想的路径，问题在哪里？

问题不在"蒸馏"本身，而在三处：

1. **直接回归 token 是错的**（BC 全家桶失败），必须回归相位 + 查表；
2. **转向/横移的上限是教师给的**（官方 token 95–270 步内倒），我们无法超越；
3. **想用 RL 的 aux 加正向价值，但替代管道缺力矩通道**（见 §14.2），所以 aux 永远是破坏源。

### 16.3 APT 循环首尾连不上，会不会越走越偏？这是问题所在吗？

**不是问题所在。** 我们专门做了闭合周期实验：把 14 组原型全部闭合（闭合误差 0.00000）后重训，
A 持平、B/C 反而变差。漂移根源在**控制器层缺参考重锚定/闭环修正**，不在数据首尾是否闭合。
数据闭合解决不了"每 5–10 步误差累积"的问题。

### 16.4 论文里还有哪些方法我们没用？

已核对并列出（标注状态）：

| 论文方法 | 我们状态 | 备注 |
|---|---|---|
| TO 数据（力矩标注） | **缺** | 无法用 PD 标签廉价替代 |
| TVAE 连续潜空间 | 试过 VAE-lite（失败） | 需力矩解码器配套才成立 |
| 力矩级解码器 | **缺** | SONIC 位置解码器替代 |
| 2Hz 门控正确语义 | 已修正（E13 正向） | naive 版被策略当钟表 |
| 完整任务+风格奖励 | **缺** | 我们只有 5 项最小奖励 |
| elevation→gait/latent 通道 | 试过（E16/E17/E21a） | 无动作流形载体，地图无效 |
| 千级并行 | **缺** | 64 envs（RTX 3060） |
| 感知蒸馏（depth/LIDAR→GRU） | 机制验证（P1） | 真实传感器未渲染 |
| latent KL + 探索衰减 | 已做 | 平坦无显著影响 |

### 16.5 凹凸不平的地面是怎么实现的？和论文像吗？

MuJoCo：hfield 高度场（两个坑已修复，见 §14.1）；Isaac：`HfRandomUniformTerrainCfg` +
显式 `np.random.seed(terrain_seed)` 保证可复现。论文用 7 类程序化地形 + 课程，我们实现了
粗糙地形 + 小台阶，**方向一致、规模小得多**。

### 16.6 如果地面是平的，是不是就能轻松完成？

**是，而且是论文要求的顺序。** 平坦直行是官方数据覆盖最厚的区域，oracle 能站住，我们的
蒸馏控制器全项通过。论文也是先做平地速度跟踪，再上地形课程。**我们已验证"先平坦、再地形"
的顺序正确**；现阶段 flat + gate-only 就是能稳定交付的结果。

### 16.7 下一步该做什么？设备要不要升级？

见 §18。一句话：**先固化平坦 + gate-only 的结果；要复现论文级地形能力才需要换硬件
（≥4096 envs）和换数据（TO 力矩）。**

## 18. 下一步建议（按优先级）

### 方案 A：固化当前成果（推荐先做，成本最低）

1. 把 E20c gate-only（anti-stop 训练的步态选择）作为正式交付：平坦全项 + rough 0.06 三地形
   9/9 前进；
2. 补完 E21b 的 stairs_hi / stones / discrete 评测，确认先验的离散地形边界；
3. 出一份"能力边界卡"：什么能稳定做（前进/倒走/慢走/跳跃/转向/横移/小台阶/0.06 粗糙），
   什么不能（0.08 以上粗糙、长时间命令切换中的跳跃、stealth）。

### 方案 B：想真正突破论文级能力（需要条件）

1. **换数据**：真 TO / 逆动力学的前馈力矩数据（这是解锁力矩级解码器的前提）；
2. **换解码器**：力矩级解码器（PD 稳定下的力矩修正），让 latent/aux 有容错载体；
3. **换潜空间**：TVAE / Gaitor 式连续 gait latent，替代离散 token 相位；
4. **换算力**：≥4096 envs（4090 / A6000 / 多卡）才能复现论文级并行；
5. **换奖励**：完整任务+风格奖励（velocity tracking + pose/foot_clearance 等），补上"必须
   前进"的压力。

### 硬件结论

- 如果只交付"平坦 + 0.06 粗糙"：**RTX 3060 12GB 够用**，不需要升级；
- 如果要复现论文级地形泛化：**需要升级**（并行规模差约 64 倍），同时需要 TO 力矩数据管线。

## 19. 术语表（人话版）

| 术语 | 意思 |
|---|---|
| token | SONIC 把"接下来怎么动"压缩成的一个 64 维离散编码 |
| 相位 | 步态周期的位置（一个步子走完算一圈，φ 从 0 到 2π） |
| 相位路由器 | 我们的核心结构：本体感受+命令 → 相位 → 查原型 token 表 |
| 原型 | 每个相位区间内官方 token 的平均值，作为"标准动作帧" |
| oracle | 直接把官方采的数据喂回去回放，作为"教师能力上限"对照 |
| aux | 强化学习额外输出的 12 维关节修正 |
| gate | 强化学习学习的"选哪个动作组"的开关 |
| elastic band | 官方模拟里把机器人拉向固定点的虚拟弹簧（数据采集时关掉了） |
| TO | 轨迹优化，论文用来生成带力矩的周期轨道的方法 |
| TVAE | 论文用的时序变分自编码器，把动作压成连续潜空间 |
| hfield | MuJoCo 的高度场地形 |
| FSQ | Finite Scalar Quantization，SONIC 用的离散量化方法 |
| 教师上限 | 官方模型/官方 token 本身能稳定做到的极限，蒸馏无法超过它 |

## 20. 最终一句话

**我们证明了：用官方 SONIC 数据蒸馏"相位路由器 + 官方解码器"，是当前条件下能做出的最强、最稳、
最便宜的 G1 无带控制器；官方 SONIC 对转向/横移等动作本来就没有长效数据能力（95–270 步上限），
这是它的架构+数据+量化特性决定的，不是我们做错了；要超越它，只能换力矩级数据/解码器、换连续潜空间、换千级并行，而不能靠继续堆辅助组件。**
