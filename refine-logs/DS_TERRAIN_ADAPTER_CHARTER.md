## 1. 主假设与研究问题

**主假设（09-05 升格，论文第一贡献候选）**：

> **在保持预训练控制器（SONIC 冻结 decoder）不变的条件下，用一个共享的
> 地形适配模块，把地形适应能力迁移到适配训练未见的动作上，同时保持原有
> 动作质量。**

成立须同时做到三件事：

1. **完成地形通行**；
2. **保留指定动作**——不把所有动作退化成普通走路。注意：权重冻结 ≠ 动作
   能力不损失，上层模块若把挥手 token 改写成走路 token，decoder 虽冻结、
   用户要求的动作仍被抹掉；
3. 不增加该动作的训练数据、不重新优化参数。

**子问题（过渡衔接，第一轮研究问题保留为主假设下的模块问题）**：

> 在复用预训练全身控制器的条件下，能否根据地形和当前接触状态，学习何时
> 切换、怎样过渡，使已有技能在未见过的地形组合中可靠执行？这种能力在哪些
> 情况下需要适配低层控制器？

过渡器承担比四分类选择器更具体的任务：①根据局部地形、身体状态和足部接触，
判断当前是否适合切换；②选择过渡开始时间、持续时间和短时动作序列；③执行
一小段后根据新状态重新规划。**候选贡献 = 对过渡可执行性的建模及其闭环
收益**；VAE、步态族数量与冻结权重都是实现选择，不是贡献本身。是否具有
方法创新，还须针对「接触条件化过渡、技能衔接、短时潜空间规划」做进一步
近邻核查（§3），当前不保证首创。

**冻结由此获得目的性理由**：新学的地形适配能力可复用 + 保住原有技能库
（实证裁决规则见 §6）。适配模块必须同时知道**「地形是什么」和「原本要做
什么动作」**，不只是选择步态；且不能默认「下肢负责地形、上肢直接播放」
成立——上肢动作改变重心与角动量，须与直接复用 SONIC 混合控制接口
（上肢指定/下肢规划）对照证明增益。

## 2. 判断修正（归因与现状）

1. **历史性能不足不能归因于冻结 decoder**。D034：同一冻结 SONIC decoder
   输入官方 RUN token，Isaac 三次 60s 回放均速 ~1.67 m/s（实现率 1.61），
   D035 打滑核验 HONEST——历史 0.35–0.45 m/s 不能作为整个 decoder 的速度
   上限。它不证明复杂地形能力，但足以要求把**数据 / VAE / 策略 / 执行
   环境**四层限制分开归因（证据：`apt_g1/outputs/sync/ds_phase0_oracle_replay_isaac.json`）。
2. **官方数据接入已有小规模进展**。D038：锚定 ref-rel 修复后，官方样例
   离线编码 → 冻结 decoder → Isaac 闭环 2×40s 零摔（物理量 97% 复现）；
   批量质检与正式训练未做，数据路线不算完成，但接口无需从零验证
   （`tracker/D.md` D038）。
3. **D031/D032 失败现象是待验证线索而非已证机制**：过栏结果随到达相位
   变化（38% 相位彩票）、平台↔石头阵过渡带集中失败——值得继续验证，
   尚不足以证明原因只有相位问题（`tracker/D.md` D031/D032）。

## 3. 文献定位：撤回的主张与四个近邻

**撤回（09-05 owner 裁定）**：`LITERATURE_SURVEY_DS_MANIFOLD.md` 中
「组合新颖性成立」「首个冻结官方部署级 token 解码器……」降级为**待验证
假设**——限定词越来越多，并不意味着研究问题越来越重要。任何「首次」
主张须先完成近邻训练方式与实验协议的对照核查。

**四个必须重点对照的近邻**（09-05 检索）：

| 近邻工作 | 已覆盖内容 | 对我方影响 |
|---|---|---|
| T-GMP（[2606.06944](https://arxiv.org/abs/2606.06944)） | 地形条件化动作流形、平滑风格转换、统一策略适应地形 | 「感知 + 流形 + 多步态转换」不能作宽泛创新主张 |
| Whole-Body Humanoid Locomotion via Motion Generation & Motion Tracking（[2604.17335](https://arxiv.org/abs/2604.17335)） | 感知驱动动作生成、闭环微调跟踪器、G1 混合地形实机通行 | 「先验动作泛化到地形」已有很近的方法，且对方明确适配了低层跟踪器 |
| Perceptive BFM（[2606.08059](https://arxiv.org/abs/2606.08059)） | 保留原始动作参考作输入，用地形感知调整接触/姿态/时序 | 与「保留动作、适应地形」设想非常接近 |
| SceneBot（[2606.27581](https://arxiv.org/abs/2606.27581)） | 统一自由运动/地形通行/全身操作；报告未见动作与环境泛化 | 「首次让多种全身动作适应地形」宽泛主张不稳 |

这不代表地形问题已彻底解决，但意味着：**只证明我们的系统也能过几种地形，
论文说服力会比较弱**。

**候选差异主张（待近邻协议对照后判定新颖性）**：保持预训练控制器冻结 +
共享适配模块 + 迁移到适配训练未见的动作 + 原动作保真。

**措辞纪律**：允许 SONIC 预训练见过某动作——论文写「**适配阶段未见**
动作」，不得写「整个系统从未见过」。留出技能若在 SONIC 预训练中出现过，
只能称「上层训练未见技能的迁移」；更强且站得住的主张 = **未见过渡条件
和地形组合**。

**竞争力口径**：不需要在所有维度击败 SOTA。可争取的优势 = 训练效率、
原技能保持、组合泛化；但必须**同时报告绝对通过能力**，不能只与自家弱
基线比较。地形解决本身不是我方主张（HANDOFF/README §1.1 口径不变：
官方组件 = 承重墙不是贡献）。

## 4. 四阶段执行框架（每阶段带退出条件）

| 阶段 | 要解决的问题 | 计划与交付物 | 退出/决策条件 |
|---|---|---|---|
| **一：建立可信的小数据集** | 官方数据能否稳定转成我们可用的动作？ | 先处理与**行走、跑步、减速及自然过渡**相关的分层样本（**官方数据独走**——09-05b owner 指令自采退役，执行协议 = `DS_OFFICIAL_DATA_PLAN.md`）；完成编码、闭环回放、接触与跟踪质检；**按原始序列和演员划分** train/val，避免相邻帧泄漏；失败片段保留原因记录 | 先拿到质量明确的小集合，再扩全量（自采采集计划退役，见 §9 与修订记录） |
| **二：定位能力限制** | 失败来自 VAE、策略，还是低层控制？ | 同一环境比较三方：官方参考 token / 经 VAE 重建的 token / 学习策略输出；先测平地，再测两类最小过渡任务 | 参考能做而策略不能 → 继续上层研究；经 VAE 后才失败 → 先修表示（VAE 双流形线接手） |
| **三：验证过渡与适配方法** | 学习过渡/适配是否优于简单切换与逐动作专门训练？ | 任务只做「平地↔踏石」与「低障碍前的步态调整」两类；先用理想高度图隔离控制问题，再加入感知噪声与延迟；并跑 §5 迁移最小实验 | 必须胜过相位/接触规则切换和直接条件策略（过渡侧）；达到 §5 成功标准（主假设立项门） |
| **四：判断是否解冻并扩展** | 冻结是否有值得保留的收益？ | 加受限低层适配对照；测试未见地形顺序、间距、进入速度及多次连续切换；随后 sim2sim 与有限实机验证 | 按 §6 裁决规则定主路线 |

**阶段二补充工具**：可用特权信息搜索切换时机和短时 token 序列，作为
「目前能找到的可执行解」参考——**搜索成功证明某种能力存在；搜索失败
不能证明 decoder 绝对做不到**。

**近期最优先交付物**：「能力存在但衔接失败」的小规模证据表（阶段二产物）
——用它决定是否值得开发过渡方法，再决定是否扩大数据与适配 decoder。
这样下一轮实验无论正负，都能直接推动论文方向选择。

## 5. 主假设最小判别实验（最关键的下一步证据）

**问题**：在少数动作上学到的地形适配，能否让一批未参与适配训练的动作
直接受益，并且没有把这些动作抹掉？

| 项目 | 最小设计 |
|---|---|
| 动作范围 | 先选**无物体接触**的上肢动作，覆盖对称/非对称/缓慢/快速 |
| 地形范围 | 平地、坡面、低台阶（先限明确可行范围） |
| 训练方式 | 一个共享适配模块，只用部分动作训练 |
| 核心测试 | **留出整个动作族**测其地形执行；另留出动作×地形组合 |
| 必要对照 | 原始 SONIC / 共享适配模块 / 逐动作专门训练 / 允许低层适配 |
| 成功标准 | **通行成功且动作保真**；同时统计新增动作所需训练量 |

- 暂不纳入：搬物、扶墙、大幅杂技（涉及额外接触或更强全身动力学约束，
  另做验证）。
- 该实验 = 主假设的立项门；过渡控制（§1 子问题）作为其实现模块在阶段三
  接续验证。

## 6. 冻结/解冻裁决规则（三对照 + 四分支）

三条对照路线：

| 路线 | 作用 |
|---|---|
| 冻结 SONIC + 学习过渡/适配模块 | 检验既有能力能否通过组合被充分利用 |
| 相同上层 + 受限低层适配 | 检验修改少量低层参数是否带来关键收益，同时测原技能退化 |
| 成熟直接关节 RL 配方 | 提供外部能力与训练成本参照，避免把自家训练不足误判为先验优势 |

裁决四分支：

1. **冻结 ≈ 适配**，且训练成本更低、原技能保持更好 → **坚持冻结**
   （有实证理由）。
2. **适配明显更强**且无显著遗忘 → **允许转向适配**，不必为最初设定辩护。
3. **两者都弱** → 先检查数据、任务与训练条件，**不得立即宣布冻结路线
   失败**。
4. **简单规则已达学习方法水平** → 停止增加网络复杂度，重新评估过渡问题
   是否具有足够研究空间。

注：E48 全关节残差三配置负结果可降低低层适配路线的优先级，但**不足以
否定所有低层适配方法**（文献前提 = 千级 envs，本地 128-envs 是规模受限
证据，非机制否证）。

## 7. 验收标准与误判防线

- **主指标**：未见组合路线上的**完整任务成功率**——跨过障碍、经过过渡并
  继续行进；站住不倒不算完成。
- **辅助指标四项**：过渡窗口跌倒率；速度跟踪；训练交互量与墙钟成本；
  原有技能保持。
- **种子纪律**：探索阶段用少量种子筛选；确认阶段用多个独立训练种子 +
  独立地形布局报告不确定性。
- **三个误判防线**：
  1. token 重建误差低、插值 lattice 合法 **≠ 过渡可执行**（重建指标只是
     必要条件，不是充分条件）；
  2. 大数据版本（VAE-L）没有提升 **≠ decoder 容量耗尽**——可能是数据
     质量/条件轴/任务设计问题，归因前先做阶段二的四层分离；
  3. 「从未见过」类表述按 §3 措辞纪律执行（适配阶段未见 ≠ 系统从未见过）。

## 8. 数据采法修正（过渡样本）

现有设计 `A → idle → B`（DS_GAIT_MANIFOLD_PLAN §3 过渡段）主要教会
**经过停顿的切换**。若论文主张运动中连续转换，过渡材料必须包含：

1. **不经 idle 的直接 A→B**（连续转换）；
2. 不同进入速度（慢/中/快进入同一切换对）；
3. 不同接触状态（双支撑/单支撑/腾空瞬间起切）。

阶段一小集合若含过渡段，按此三类补齐；A 线 Phase 1 网格重启时按本节修订
其过渡段采法（原 36 段设计保留为停顿型子集，不删除）。
