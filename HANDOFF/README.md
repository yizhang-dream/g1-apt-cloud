## 1. 项目一句话

在 Unitree G1 人形上，用 NVIDIA GEAR-SONIC 的官方 token 数据 + 冻结解码器，
复现 Science Robotics 2026 的 APT-RL（动作预训练 Transformer 强化学习）
论文管线（TO 数据 → 潜空间 → RL 增强 → 地形泛化），并回答"蒸馏先验是否
必要、论文机制在我们的替代管道里是否成立"。

## 1.1 项目身份定位：什么"算我们的"，什么"不算"

> 防止误把"复刻 SONIC"当成项目本身。项目不是"重装 SONIC"，而是"用 SONIC
> 冻结解码器当底板，验证 APT-RL 论文的 RL 机制在替代先验上是否成立"。

- **官方组件 = 底板（承重墙），不是贡献**：planner / encoder / decoder 是给定
  的实验材料，是"蒸馏先验是否必要"这个消融的前提（必须有个官方 decoder 才能
  测"没有它行不行"）。
- **属于我们的三样东西**：
  1. **问题本身**：论文用自己 TO 先验 + 自己解码器；我们问的是"论文 RL 机制
     搬到 SONIC 这个第三方冻结先验上还成立吗"（跨先验迁移，论文和 SONIC 都不问）。
  2. **蒸馏层（自研架构）**：相位路由器、token VAE——官方没有，是我们替代
     planner 的 command→token 蒸馏。
  3. **双解耦潜空间（E37/E39，自研机制）**：方向 + 速度对抗解耦。
- **两条线定位不同**：
  - **MQ 线（planner 复刻，MQ08/MQ09）= 地基/校准**：忠实复现官方 SONIC，自己
    不是创新，价值是纠正错误归因（0.08 悬崖 = 蒸馏路径边界，非解码器本身）。
  - **E/D 线（蒸馏 + RL 增强 + 潜空间）= 贡献**：这才是"我们的东西"。
- **产出是发现，不是代码复用**：蒸馏先验必要、冻结 decoder 速度天花板 ~0.35、
  aux 永远破坏、双解耦修漂移、0.08 悬崖归因修正——这些经验结论（含负结果）
  才是可交付物。

### 阶段 7：速度/方向条件化潜空间（E28–E40，2026-08-13）
- E27 只得半速（0.32 vs 先验 0.8），E28–E30 归因消融（解冻步频/奖励重调/
  KL 先验对齐）定性：**~0.3–0.35 m/s 是冻结 walk 解码器流形的固有速度
  天花板**（修正 E27"半速=样本效率代价"）。
- E31 速度条件化 VAE（D(z,φ,v)→token）**打破 ~0.35 上限（vx 0.535，+54%）**
  但自带系统性左转偏置；E32（heading 奖励）/E33（开环 yaw 补偿）/
  E34（yaw 域随机化）均无法修复——偏置是流形技能固有特征。
- E35 方向条件化 VAE（D(z,φ,v,ψ)→token）`DirSpeedPhaseTokenVAE`，**修复漂移**（disp/vx 0.31→0.93 接近直行，disp 16.3m）但速度回落 ~0.3（未被激励选快 bin）。
- E36 速度激励（E35 + anti-stop-thresh 0.4 + progress-scale 0.5）：vx 0.372
  （+26%）/ disp 15.4m 但直行掉回 0.69 → 推快 z 重新引入转向偏置，简单奖励
  速度激励不能实现"快且直"。
- E37 方向解耦 VAE（对抗式方向分类头，让 z 方向不变）：**快且直达成** ——
  A vx 0.370 / disp 21.55m / 直行 0.97（同 vx 下 E36 直行 0.69）。根因 =
  z 隐式编码方向；解耦后漂移消除。
- E38 更高速度激励（E37 + anti-stop-thresh 0.5 + progress 1.0）：A vx 0.399
  （+8%）/ disp 19.4m（-10%）/ 直行 0.81（vs E37 0.97）。**方向解耦不是解锁
  0.535 快 bin 的钥匙**——它修好 0.37 档漂移，但解耦后 z 速度天花板 ≈0.40
  （低于 E31 未解耦的 0.535），速度上限与方向纠缠是两个独立约束。
- E39 双解耦 VAE（方向+速度对抗头，E38 高激励）：A vx 0.417 / disp 24.65m /
  直行 0.98 —— **"速度纠缠在 z 里"假设成立**：同一高激励下 E38 掉直行 0.81、
  E39 又快又直，disp 24.65m 为潜空间线历史最佳（超越 E37 21.55m）。
- E40 双解耦 × 更高激励（thresh 0.6 + progress 1.5）：A vx 0.456 / disp
  24.40m / 直行 0.89（vs E39 0.417/24.65m/0.98）→ **E39 是甜点**：激励再推
  速度增益边际化、C/D 机动性退化（切换 disp 10m→3m），0.535 仍不可及。
- 渲染管道升级：`replay_render_mujoco.py`（MuJoCo 3D 真实模型 offscreen，
  MUJOCO_GL=egl）产出 e29/e31/e35_mujoco.mp4；骨架动画降级为调试辅助。

## 3. 核心结论速查（11 条）

1. 蒸馏先验（冻结相位路由器 + SONIC 解码器）在当前设备/数据条件下是最优
   可用控制器：平坦全项通过，rough 0.06 3/3。
2. 同等预算 vanilla RL（直出关节）无法行走（E9/E11 0/3）。
3. aux 关节偏移通道在 SONIC 位置 token 管道下永远是破坏源（E2-E22b、E25
   消融全部一致）；复现论文 aux 正向价值需力矩级解码器 + 自洽 TO/ID 数据。
4. 2Hz 门控是唯一被验证为正的论文机制（E13）。
5. gate 选择（anti-stop 压力下）能收敛到选先验最优组，无损但不增益（E20c）。
6. 连续潜空间（相位插值/锚定）无损但机制中性；E26 全项达标但 A 仅 ≈97%
   基线，地形 0.08 无增益。
7. 相位条件化 token VAE + 步态时钟 + z_walk warm-start 让"无行为先验"
   RL 能学会行走（E27：19m，vx 0.32），但 **E28–E30 归因证明该半速是
   冻结 walk 解码器流形的固有速度天花板（~0.3 m/s，非样本效率代价）**。
8. 力矩级数据（ID）改善前馈但单独不能解锁论文式控制。
9. 千级并行正解 = mjlab（MuJoCo-Warp）官方配方，独立于蒸馏管道；3060
   12GB 可跑 1024 envs（0.84GB），4096 默认需 24GB GPU。
10. "蒸馏（路由器）是否必要"（修正口径）：仅在管道内成立——E27（有解码
    器、无路由器）可走但约 0.4× 位移（19m vs 47m）→ 路由器不必要但
    ≈2.5× 提速；SONIC 解码器/token 流形才是关键先验（E9/E11 直出关节
    0/3）。mjlab 是"无 SONIC 组件"的官方从零配方对照（**已完成 6500 iters，
    fell_over 0.125**，model_6499.pt + policy.onnx），回答官方配方不用解码
    器的可行性，不直接回答"蒸馏是否必要"。
11. **速度条件化 VAE 破 ~0.35 上限但自带转向偏置；方向条件化修漂移**：
    E31 速度条件化 VAE 达 vx 0.535（+54%）但系统性左转偏置非奖励（E32）/
    补偿（E33）/DR（E34）可修；E35 方向条件化 VAE 修复漂移（disp/vx
    0.31→0.93）但速度回落 ~0.3。E36 速度激励 vx 0.372（+26%）但直行掉回
    0.69。**E37 方向解耦 VAE 修好漂移：快且直达成（vx 0.370 / disp 21.55m /
    直行 0.97）**——根因是 z 隐式编码方向，对抗式解耦让 z 方向不变后消除。
12. **E38 更高速度激励（E37 + anti-stop-thresh 0.5 + progress 1.0）**：A vx
    0.399（+8%）/ disp 19.4m（-10%）/ 直行 0.81（vs E37 0.97）。**方向解耦
    不是解锁 0.535 快 bin 的钥匙**——它修好 0.37 档漂移，但解耦后 z 速度
    天花板 ≈0.40（低于 E31 未解耦的 0.535）：速度上限与方向纠缠是两个独立
    约束。
13. **E39 双解耦（方向+速度）VAE**：同一高激励下 vx 0.417 / disp 24.65m /
    直行 0.98（vs E38 0.399/19.4m/0.81）→ **"速度纠缠在 z 里"假设成立**，
    潜空间线历史最佳位移（超越 E37 21.55m）。
14. **E40 更高激励（E39 + thresh 0.6 + progress 1.5）**：vx 0.456（+9%）
    但直行 0.98→0.89、C/D 机动性退化 → **E39（0.417/24.65m/0.98）仍是
    双解耦线甜点**，0.535 速度记录在解耦线仍不可及。
15. **从零 + 冻结解码器（E45→E47，"务必用解码器"的实证，2026-08-14）**：
    vanilla 从零直出关节学出**蹲蹭漏洞**（h_min 0.20、body 系 vx 假速度、
    世界 disp=0）；改用 latent + 冻结 SONIC 解码器后**从零（无 warm start）
    也能真走路**——E45 disp 14m、E46+E39 VAE 破速度天花板（vx 0.418）、
    E47+heading → **vx 0.42 / 直行 0.944 / disp 23.8m、A/B/C/D 全过**。→
    冻结解码器是防作弊承重墙；速度+方向双解耦 VAE + 轻 heading 足以让从零
    策略快且直。〔E47 的 D"跳跃"是假阳性——E39 VAE 只覆盖 WALK token。〕
